# 풀스택 웹 문제집

[문제 풀기](./index.html) · [전체 목차](../index.html) · [처음 읽는 기술 안내서](../technology-guide.md)

이 저장소의 프로그램과 학습 트랙에 쓰이는 기술을 초보자 눈높이로 연습합니다. 각 문항에는 네 개의 보기, 한 개의 정답, 한국어 해설과 관련 학습 문서 링크가 있습니다.

## 실행 방법

저장소 루트에서 다음 명령을 실행합니다.

```bash
npm install
npm run serve:workbook
```

브라우저에서 `http://127.0.0.1:4187/`를 열면 **웹 문제집이 바로 표시됩니다**. 기존 워크북은 위쪽 **기존 워크북 455문항**, 설명·실습 목차는 메뉴의 **17단계 실습 목차**에서 선택합니다. HTML 파일을 더블 클릭하는 방식은 브라우저가 문제 데이터 읽기를 제한할 수 있으므로 위 서버를 사용하세요.

전체 목차의 01~17단계 카드에서 **웹으로 풀기**를 누르면 해당 과목의 문제로 바로 이동합니다. 17단계는 기존 워크북의 기술·통합 면접 문제로 연결됩니다. 문제집에서 정답을 확인한 뒤 **기존 워크북에서 더 알아보기**로 원문과 실습을 이어갈 수 있습니다.

## 학습 방법

1. **학습 홈**에서 과목별 문항 수와 진도를 보고 **학습 시작**을 누릅니다. 이미 풀었다면 남은 미풀이부터 시작합니다. 기본기 3,000문항과 **기존 워크북 455문항**을 위쪽 탭에서 선택합니다.
2. 보기 하나를 고른 뒤 **정답 확인**을 누릅니다. 그때 정오답, 정답 보기와 해설이 나타납니다. 선택만 한 보기는 점수에 반영되지 않습니다.
3. **기존 워크북에서 더 알아보기**로 원문을 확인하거나 **이 문제 다시 풀기**로 재도전합니다.
4. **다음**, 목록 순번, **문항 바로 가기**로 이동합니다. 과목·범위·검색을 바꾸고 **적용**하거나 **순서 섞기**로 다른 순서로 풀 수 있습니다.
5. **오답노트** 또는 과목 카드의 **오답 복습**을 누르면 정답을 가리고 다시 풉니다. 정답으로 고쳐도 현재 복습 목록은 유지되며, **최신 오답으로 갱신**하면 맞힌 문제는 빠집니다. 새로고침해도 현재 복습 목록과 순서를 유지합니다.
6. **학습 기록**에서 과목별 풀이 진도·정답·오답을 확인합니다. 브라우저를 옮기기 전에 **기록 내보내기**로 JSON 파일을 보관하고, 같은 문제집에서 **기록 불러오기**로 합칠 수 있습니다. 같은 문항은 파일의 답으로 갱신하며, 다른 문제집·버전·잘못된 답이 든 파일은 거절합니다.

풀던 화면, 적용한 과목·범위·검색, 섞은 목록과 현재 문제, 아직 제출하지 않은 선택도 자동 저장합니다. **학습 홈 → 이어서 풀기**로 돌아갈 수 있습니다. 기존 문서의 문항별 링크는 해당 문제로 바로 연결합니다.

여러 탭에서 공부해도 각 탭의 풀던 위치와 미제출 선택을 따로 복구합니다. 제출한 답과 과목별 진도는 탭 사이에서 공유하고, 새 탭이나 브라우저를 다시 열면 마지막으로 저장한 위치에서 이어 풀 수 있습니다. 다른 탭에서 별개의 문제를 제출해도 현재 보고 있는 해설과 작성 중인 선택을 유지합니다.

목차나 원문에서 과목·문항 링크를 새로 열면 링크가 지정한 대상으로 이동합니다. 같은 주소에서 새로고침하거나 뒤로 돌아올 때는 풀던 상태를 복구합니다. 검색어가 전체 문항 번호와 일치하면 그 문제만 표시하며, 짧은 번호나 키워드는 부분 검색합니다. 예를 들어 `P100`은 한 문제, `P10`은 해당 문자열을 포함한 문제를 찾습니다.

점수는 문항별 **마지막으로 제출한 답**을 기준으로 계산합니다. 같은 문제를 여러 번 풀어도 푼 문항 수가 중복 증가하지 않습니다. 다시 풀기를 눌렀다가 답을 제출하지 않으면 이전 기록을 유지합니다.

학습 기록은 현재 브라우저·주소의 localStorage에 저장합니다. 서버 계정이나 기기 간 자동 동기화는 없으므로 브라우저를 바꾸거나 사이트 데이터를 지우기 전에 파일로 내보내세요. 저장소 사용이 차단되면 화면에 안내하고 해당 페이지에서만 계속 풀고 파일로 내보낼 수 있습니다. **이 문제집 기록 초기화**는 확인 후 현재 문제집의 답과 이어 풀기 위치만 초기화하며, 다른 문제집·트랙의 빈칸·체크리스트·Career Hub 데이터는 바꾸지 않습니다.

기존 2,000문항의 ID·보기·정답·해설과 기록 버전을 유지했습니다. 같은 브라우저와 같은 주소에서 사용했다면 이전 풀이 기록을 이어서 복습할 수 있고, 추가된 P1601~P2600은 아직 안 푼 문제로 표시됩니다.

## 서술형 전환 4지선다

문제집 서버에서 학습 문서를 열면 **문서 안에서도 바로 보기 선택 → 정답 확인 → 해설 확인**을 할 수 있습니다. 선택한 답과 정답을 글자와 색으로 구분하며, **다시 풀기**로 재도전합니다. 페이지 상단에서 풀이 현황과 **다음 미풀이로 이동**을 사용할 수 있습니다. 휴대폰에서도 같은 기능을 제공합니다.

문서와 전환 문제집은 같은 브라우저·주소의 풀이 기록을 공유합니다. 다른 문서에서 푼 기록도 보존하며, 정답을 다시 제출하면 마지막 답으로 갱신합니다. GitHub나 파일 원문에서는 기존 목록과 접힌 해설이 표시됩니다. JavaScript를 끈 경우에는 접힌 정답·해설로 확인할 수 있습니다.

[전환 문제집 열기](./index.html?bank=written)에서 **455문항**을 풀 수 있습니다. 실행 명령은 위의 `npm run serve:workbook`과 같습니다. 기본기 3000제와 기록을 따로 저장하며 한 문제집의 초기화가 다른 문제집의 기록을 지우지 않습니다. 기존 451문항의 내용·ID·정답·기록 버전을 유지해 이전 풀이 기록을 복구합니다. 추가 W452~W455는 아직 안 푼 문제로 표시됩니다.

설명·면접·자가 점검 문항은 모두 **보기 네 개·정답 한 개·한국어 해설**로 제공합니다. 단계별 README·문제·정답 문서, 종합 워크북, 기술 안내서와 로드맵을 함께 검사합니다. SQL 실습 소스의 실행 계획 관찰 질문도 [L02 선택형 문항](./index.html?bank=written&question=W147)으로 연결합니다. 같은 개념은 기존 문항을 재사용하므로 총 문항 수는 455개이고, 코드의 학습용 빈칸과 개인 실행 기록은 직접 작성합니다.

기존 CS 21문제, 기술 면접 카드 77개, 인성 질문 10개는 원문 ID와 전환 문항의 연결을 보존합니다. 개인 경험을 묻던 질문은 적절한 설명·근거·답변 방식을 고르는 문제입니다. 선택한 답이 개인의 실제 경험을 증명하는 것은 아닙니다. 단계별 README, 종합 워크북, 취업 로드맵을 서버에서 열면 문서 안에서 직접 선택·채점하고, 문항별 링크로 집중 모드에 이동할 수 있습니다. 같은 주제를 여러 문서에서 확인하는 문항도 포함합니다.

원본을 고친 뒤 `npm run build:written`을 실행하면 웹 데이터와 문서의 선택형 구간을 함께 갱신합니다. 문서의 생성 구간은 원본에서 수정하세요. 이어서 `npm run verify`로 문항 누락·보기·정답·문서 일치를 확인합니다. 의미나 정답이 바뀌면 빌드 스크립트의 `version`을 올립니다.

공통 개념 중 격리 수준은 SQL 표준의 최소 보장과 DB 구현을 구분하며, Node 비동기 I/O와 OWASP 분류는 각각 [PostgreSQL 격리 수준 문서](https://www.postgresql.org/docs/current/transaction-iso.html), [Node 이벤트 루프 문서](https://nodejs.org/en/learn/asynchronous-work/event-loop-timers-and-nexttick), [OWASP Top 10 2021](https://top10.owasp.org/2021/)을 참고합니다. OWASP 문항은 기존 트랙의 **2021판** 기준입니다.

추가 자가 점검은 [TypeScript 좁히기·never](https://www.typescriptlang.org/docs/handbook/2/narrowing.html), [strict 옵션](https://www.typescriptlang.org/tsconfig/strict.html), [Git ignore 규칙](https://git-scm.com/docs/gitignore), [Compose 시작 순서](https://docs.docker.com/compose/how-tos/startup-order/)를 참고합니다. Compose의 컨테이너 시작과 DB 준비 상태, 정적 타입 검사와 런타임 검증, ignore 규칙과 이미 추적된 파일을 구분합니다.

비밀번호 정책 문항은 [OWASP 비밀번호 저장 안내](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)와 [인증 안내](https://cheatsheetseries.owasp.org/cheatsheets/Authentication_Cheat_Sheet.html)를 확인하고 6단계 원본 코드의 실제 동작과 보완할 정책을 구분합니다. 비용 값 12를 모든 서비스의 단일 정답으로 취급하지 않습니다.

문항의 코드는 별도 연습 조건입니다. 실제 프로그램의 설정을 묻는 경우에는 Career Hub·Note Hub 등 대상을 명시합니다. 제공된 설명을 읽고 정답을 고르는 것은 기존 구현 실습의 완료를 대신하지 않습니다. 하루 20문항씩 총 150회 분량으로 사용해 보세요.

- [questions.json](./questions.json): 브라우저가 읽는 전체 문제집. 정답도 들어 있는 학습 자료이며 비공개 시험용은 아닙니다.
- [core.js](./core.js): 채점, 복습 필터, 기록 복구 규칙.
- [app.js](./app.js): 라디오 버튼·해설·진행 기록을 화면과 연결하는 코드.

문항을 수정한 뒤 루트에서 실행합니다.

```bash
npm run build:quiz
npm run verify
```

검증은 문항 수·분야·보기 네 개·정답 범위·해설·중복·실제 문서 경로와 생성 결과의 일치를 확인합니다. 실행 가능한 JavaScript 1,160문항은 실제 실행 출력으로, TypeScript 120문항은 타입 표기를 제거한 실행 출력으로, SQL 계산·조인 240문항은 임시 SQLite DB로 기대값을 대조합니다. 이 SQL 문제는 Oracle 전용 문법을 포함하지 않는 공통 구문입니다. 채점·재도전·복습·손상된 기록 복구와 기존 1,000문항 및 2,000문항의 동일성도 테스트합니다. 원본 정답이나 ID의 의미가 달라지면 `build-quiz.js`의 `version`을 올려 이전 풀이 기록이 새 문제에 적용되지 않게 합니다.
