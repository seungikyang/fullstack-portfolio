한 번에 모두 읽지 말고, 막힌 문제의 1단계부터 차례로 확인하세요.

## 문제 1. 목록 조회 API

### 1단계. 개념 환기

- Express의 `res.json`은 JavaScript 배열이나 객체를 JSON 응답으로 보냅니다.
- 이 단계의 게시글 원본은 서버 메모리의 `posts` 배열입니다.

### 2단계. 접근 방향

- 라우트 밖에 선언된 게시글 배열 이름을 확인하세요.
- `GET /posts` 콜백에서 새 빈 배열을 만들지 말고 현재 배열을 응답하세요.

### 3단계. API 수준

```js
app.get("/posts", (req, res) => {
  res.json(/* 현재 게시글 배열 */);
});
```

## 문제 2. 단건 조회 API

### 1단계. 개념 환기

- URL 파라미터는 문자열로 들어오지만 게시글 id는 숫자입니다.
- `find`는 조건에 맞는 첫 배열 요소를 반환합니다.

### 2단계. 접근 방향

- `req.params`에서 id를 읽어 숫자로 변환하세요.
- 그 숫자로 기존 `find` 조건이 같은 게시글을 찾도록 연결하세요.

### 3단계. API 수준

```js
const id = Number(/* URL 파라미터의 id */);
const post = posts.find((item) => item.id === id);
```

## 문제 3. 게시글 생성 API

### 1단계. 개념 환기

- JSON 요청 body는 `express.json()` 미들웨어를 거친 뒤 `req.body`에서 읽습니다.
- 생성 응답은 새 자원과 생성 상태 코드를 함께 반환합니다.

### 2단계. 접근 방향

- 새 게시글 객체를 만드는 위치를 찾으세요.
- 제목과 내용의 고정값을 요청 body의 같은 이름 필드로 바꾸세요.
- 기존 id 생성과 배열 추가 코드는 유지하세요.

### 3단계. 객체와 응답 수준

```js
const newPost = {
  id: /* 기존 id 생성 방식 */,
  title: req.body./* 제목 필드 */,
  content: req.body./* 내용 필드 */,
};

res.status(/* 생성 상태 코드 */).json(newPost);
```

## 문제 4. 게시글 수정 API

### 1단계. 개념 환기

- 수정은 먼저 대상을 찾고, 그다음 요청값을 반영하는 순서입니다.
- 요청값이 없을 때 기존 값을 유지하려면 대체값을 두어야 합니다.

### 2단계. 접근 방향

- 단건 조회와 같은 방식으로 id를 구해 게시글을 찾으세요.
- 제목과 내용 각각에 “새 값이 있으면 새 값, 없으면 기존 값” 규칙을 적용하세요.
- 없는 게시글의 404 흐름은 그대로 두세요.

### 3단계. API 수준

```js
const id = Number(/* URL 파라미터 */);
const post = posts.find(/* 같은 id를 찾는 조건 */);

post.title = req.body.title || /* 기존 제목 */;
post.content = req.body.content || /* 기존 내용 */;
```

## 문제 5. 게시글 삭제 API

### 1단계. 개념 환기

- 삭제도 URL 파라미터 문자열과 숫자 id의 타입을 맞춰야 합니다.
- 현재 코드는 id를 구한 뒤 배열에서 위치를 찾아 제거하는 흐름입니다.

### 2단계. 접근 방향

- 수정 라우트에서 id를 만드는 방식을 다시 사용하세요.
- 이후의 `findIndex`, 404, 삭제 응답 코드는 건드리지 마세요.

### 3단계. API 수준

```js
app.delete("/posts/:id", (req, res) => {
  const id = Number(/* req.params의 필드 */);
  // 기존 삭제 흐름
});
```

3단계까지 확인한 뒤에도 막히면 마지막으로 [정답 예시와 비교하세요](./answers.md).
