## 문제 1. HTML 뼈대 채우기

### 1단계. 개념 환기

- HTML 요소의 내용은 시작 태그와 종료 태그 사이에 씁니다.
- 이미지의 `src`는 파일 위치, `alt`는 이미지를 보지 못할 때 전달할 설명입니다.
- `mailto:` 링크에는 연락받을 이메일 주소가 들어갑니다.

### 2단계. 접근 방향

- `starter/index.html`을 위에서 아래로 읽으며 `____`를 하나씩 자기 정보로 바꾸세요.
- 이미지 파일이 현재 HTML 파일에서 어느 경로에 있는지 먼저 확인하세요.
- 관심 기술 목록은 같은 형태의 `li`를 반복하되, 실제로 학습 중인 기술을 적으세요.

### 3단계. 태그와 속성 수준

```html
<title>페이지를 구분할 제목</title>
<img src="____" alt="이미지 설명" />
<a href="mailto:이메일 주소">연락하기</a>
<li>관심 기술 하나</li>
```

위 뼈대의 설명 부분만 자신의 값으로 바꾸고, 완성된 문서 전체를 복사하지 마세요.

## 문제 2. CSS 꾸미기

### 1단계. 개념 환기

- flexbox는 한 방향의 배치, grid는 행과 열을 함께 다루는 배치에 잘 맞습니다.
- `:hover`는 마우스가 요소 위에 있을 때만 적용되는 상태 선택자입니다.
- 미디어 쿼리는 화면 너비 같은 조건에 따라 스타일을 바꿉니다.

### 2단계. 접근 방향

- 각 `빈칸` 주석이 요구하는 배치가 한 줄인지 격자인지 먼저 판단하세요.
- 프로필 영역의 정렬과 기술 카드 영역의 정렬을 서로 다른 레이아웃 도구로 처리하세요.
- 데스크톱 스타일을 먼저 확인한 뒤, 좁은 화면에서 쌓이는 방향만 바꾸세요.

### 3단계. 속성 수준

```css
selector {
  display: /* flex 또는 grid 중 목적에 맞는 값 */;
}

selector:hover {
  background: /* 기본색과 구분되는 색 */;
}

@media (max-width: /* 기준 너비 */) {
  selector {
    flex-direction: /* 세로로 쌓는 방향 */;
  }
}
```

## 문제 3. 설명하기

### 1단계. 개념 환기

- 시맨틱 태그는 영역의 의미를 브라우저와 사람에게 전달합니다.
- 레이아웃 도구 선택은 모양보다 데이터가 한 방향인지 두 방향인지로 설명하면 좋습니다.
- 반응형 설계는 작은 화면에서도 읽기와 조작이 가능하게 만드는 작업입니다.

### 2단계. 접근 방향

- 각 질문에 정의 한 문장과 자신의 코드 근거 한 문장을 붙이세요.
- “좋아서 사용했다”보다 “이 영역이 어떤 구조라서 선택했다”로 이유를 설명하세요.
- 모바일 개발자 도구에서 실제로 달라진 배치를 보고 답에 포함하세요.

### 3단계. 답변 틀

```text
저는 [영역의 의미/배치 특성] 때문에 [태그/레이아웃 도구]를 사용했습니다.
코드에서는 [파일과 선택자]에 적용했고, 화면 너비가 줄면 [관찰한 변화]가 생깁니다.
```

3단계까지 확인한 뒤에도 막히면 마지막으로 [정답 예시와 비교하세요](./answers.md).
