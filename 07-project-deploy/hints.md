## 문제 1. API 주소 연결하기

### 1단계. 개념 환기

- 프론트엔드와 API가 같은 origin에서 실행되면 현재 origin 기준 상대 경로를 쓸 수 있습니다.
- API 기본 주소와 엔드포인트 경로가 합쳐져 최종 요청 URL이 됩니다.

### 2단계. 접근 방향

- `fetch` 호출에서 `API_BASE` 뒤에 이미 `/api/...`가 붙는지 확인하세요.
- 별도 호스트나 포트를 덧붙이지 않도록 기본 주소를 정하세요.

### 3단계. URL 조합 수준

```js
const API_BASE = /* 같은 origin을 유지하는 값 */;
fetch(`${API_BASE}/api/posts`);
```

## 문제 2. 게시글 목록 렌더링하기

### 1단계. 개념 환기

- 템플릿 리터럴은 객체 필드를 HTML 문자열에 삽입할 수 있습니다.
- 날짜 원본은 기존 `formatDate` 함수를 거쳐 표시용 문자열로 바꿉니다.

### 2단계. 접근 방향

- 카드 제목 위치에는 현재 순회 중인 게시글의 제목을 넣으세요.
- 메타 정보에는 작성자와 변환한 작성일을 각각 넣으세요.
- HTML 구조나 클래스 이름은 바꾸지 마세요.

### 3단계. 객체 접근 수준

```js
posts.map((post) => `
  <h2>${/* post의 제목 */}</h2>
  <p>${/* post의 작성자 */} · ${formatDate(/* 생성 시각 */)}</p>
`);
```

## 문제 3. 게시글 작성하기

### 1단계. 개념 환기

- 폼 입력 요소의 현재 값은 `value`에서 읽습니다.
- API에 보낼 객체의 키는 서버가 읽는 body 필드 이름과 맞아야 합니다.
- `trim`으로 공백만 있는 입력을 정리할 수 있습니다.

### 2단계. 접근 방향

- 제목, 작성자, 본문 입력 요소를 payload의 같은 의미 키에 연결하세요.
- 세 값 모두 문자열 양끝 공백을 제거하세요.
- 이후 `fetch` 옵션과 폼 초기화 흐름은 유지하세요.

### 3단계. payload 형태 수준

```js
const payload = {
  title: /* 제목 입력값 정리 */,
  author: /* 작성자 입력값 정리 */,
  content: /* 본문 입력값 정리 */,
};
```

## 문제 4. 서버에서 body 읽기

### 1단계. 개념 환기

- 서버는 `req.body`에서 JSON 요청의 필드를 읽습니다.
- 클라이언트 payload의 키와 서버가 읽는 키가 정확히 같아야 합니다.

### 2단계. 접근 방향

- 새 게시글 객체의 제목, 작성자, 본문을 각각 요청 body에 연결하세요.
- 작성자만 생략됐을 때 기본 문자열을 사용하세요.
- id와 생성 시각을 만드는 기존 코드는 유지하세요.

### 3단계. 요청 body 수준

```js
const newPost = {
  title: req.body./* 제목 */,
  author: req.body./* 작성자 */ || /* 기본 작성자 */,
  content: req.body./* 본문 */,
};
```

## 문제 5. 배포 준비하기

### 1단계. 개념 환기

- 배포 서비스는 의존성 설치·빌드 명령과 서버 시작 명령을 구분합니다.
- 운영 포트는 플랫폼이 환경 변수로 전달하는 경우가 많습니다.

### 2단계. 접근 방향

- `package.json`의 scripts와 서버의 listen 코드를 함께 확인하세요.
- 배포 점검표의 각 칸에 실제 이 저장소에서 실행되는 명령을 적으세요.
- 로컬 고정 포트와 배포 환경 변수의 우선순위를 설명하세요.

### 3단계. 설정 형태 수준

```js
const port = process.env.PORT || /* 로컬 기본 포트 */;
```

```text
Build Command. 의존성 설치 또는 빌드에 쓰는 실제 명령
Start Command. 서버 프로세스를 시작하는 실제 명령
```

3단계까지 확인한 뒤에도 막히면 마지막으로 [정답 예시와 비교하세요](./answers.md).
