## 기술을 쓰는 이유와 동작 흐름

처음 보는 용어는 [전체 기술 안내서](../technology-guide.md)와 함께 읽으세요. 아래 흐름은 실습을 이해하기 위한 안내이며, 빈칸과 완료 체크는 직접 진행합니다.

| 기술 | 무엇이고, 왜 필요한가요? | 이 실습에서는 어떻게 쓰나요? |
| --- | --- | --- |
| 브라우저 JavaScript·DOM | DOM은 HTML을 코드로 읽고 바꾸는 구조입니다. 입력과 서버 데이터를 실제 화면에 연결하려고 사용합니다. | [public/app.js](./public/app.js)가 [index.html](./public/index.html)의 입력·목록 요소를 다룹니다. |
| fetch·JSON | fetch는 브라우저의 HTTP 요청 기능이고, JSON은 데이터를 담는 텍스트 형식입니다. 화면 코드와 서버 사이에서 게시글을 전달합니다. | `app.js`가 목록을 요청하고 작성 내용을 서버로 전송합니다. |
| Express·정적 파일 제공 | Express는 요청 처리 도구이고, 정적 파일은 HTML·CSS·JS처럼 그대로 보내는 파일입니다. 한 서버에서 화면 파일과 API를 함께 제공하게 합니다. | [server.js](./src/server.js)의 정적 파일 처리와 `/api/posts` 라우트가 역할을 나눕니다. |
| 환경 변수 | 프로그램 실행 때 외부에서 주는 설정입니다. 배포 환경이 정한 통신 포트를 사용할 수 있게 합니다. | [.env.example](./.env.example), `server.js`, [배포 점검표](./deploy-checklist.md)를 연결해 읽습니다. |

**게시글 작성의 처리 순서:** 폼 제출 → 입력을 JSON으로 전송 → 서버가 메모리 목록 갱신 → 작성 응답 반환 → 브라우저가 목록 재요청 → 새 목록을 화면에 표시. 첫 화면의 HTML 요청과 이후 게시글 API 요청은 서로 다른 요청입니다.

**직접 관찰하기:** 개발자 도구 Network(네트워크)에서 작성 요청 뒤에 목록 조회가 이어지는지 확인하세요. 서버 재시작 시 글은 초기화됩니다. 현재 화면 코드는 HTTP 실패 상태를 따로 검사하지 않으므로 요청 완료만으로 저장 성공을 단정하지 말고 응답을 확인합니다. Career Hub에서는 이 흐름에 React·인증·저장·오류 처리가 더해집니다.

## 실행 방법

```bash
cd 07-project-deploy
npm install
npm run dev
```

브라우저에서 `http://localhost:4300`을 열어 확인하세요.

## 프로젝트 구성

- `src/server.js`는 API 서버와 정적 파일 제공을 담당합니다.
- `public/index.html`은 화면 구조를 담당합니다.
- `public/app.js`는 API 호출과 화면 렌더링을 담당합니다.
- `public/styles.css`는 최종 프로젝트 화면 스타일을 담당합니다.
- [배포 점검표](./deploy-checklist.md)는 배포 전 확인 목록입니다.

## 학습 순서

1. `public/index.html`과 `public/styles.css`에서 화면 구조를 먼저 확인합니다.
2. `public/app.js`의 문제 1~3에서 API 주소 → 목록 렌더링 → 게시글 작성 순서로 연결합니다.
3. `src/server.js`의 문제 4에서 브라우저가 보낸 body를 서버 데이터로 바꿉니다.
4. 앱을 실행해 브라우저 이벤트 → fetch → Express 라우트 → JSON 응답 → 화면 갱신 순서를 따라갑니다.
5. 문제 5와 `deploy-checklist.md`에서 환경 변수, 실행 명령, 배포 전 확인 사항을 점검합니다.
6. 막히면 `hints.md`의 1단계부터 3단계까지 필요한 만큼만 봅니다.
7. 그래도 해결되지 않을 때만 `answers.md`와 비교하고 다시 직접 고칩니다.

## 면접 연습

### 브라우저에서 버튼을 누른 뒤 서버까지 어떤 순서로 요청이 이동하는지 설명해보세요.

사용자가 버튼을 누르면 브라우저에서 클릭 이벤트가 발생합니다. 프론트엔드 JavaScript가 입력값을 읽고 `fetch`로 API 요청을 보냅니다. Express 서버는 라우터에서 요청을 받아 데이터를 처리한 뒤 JSON 응답을 보내고, 브라우저는 응답을 받아 화면을 다시 렌더링합니다.

### 배포 환경에서 `PORT`를 직접 고정하면 안 되는 이유를 설명해보세요.

Render, fly.io, Heroku 같은 배포 환경은 실행 시점에 사용할 포트를 환경 변수로 주입하는 경우가 많습니다. 코드에서 포트를 `4000`처럼 고정하면 플랫폼이 열어준 포트와 맞지 않아 외부 접속이 실패할 수 있습니다. 그래서 `process.env.PORT || 기본값` 형태로 운영 환경의 포트를 우선 사용해야 합니다.

### 메모리 저장소와 DB 저장소의 차이를 설명해보세요.

메모리 저장소는 빠르고 간단하지만 서버 재시작 시 데이터가 사라지고 여러 서버가 같은 데이터를 공유하기 어렵습니다. DB 저장소는 별도 저장 시스템에 데이터를 보존하므로 재시작 후에도 유지되고 검색, 정렬, 동시성 처리에 유리합니다. 학습 초기에는 메모리 배열로 흐름을 익히고, 실제 서비스에는 DB를 사용해야 합니다.
