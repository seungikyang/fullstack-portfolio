## 문제 1. 회원가입 완성하기

### 1단계. 개념 환기

- 비밀번호는 원문이 아니라 느린 단방향 해시로 저장해야 합니다.
- bcrypt 해시는 비동기 작업이므로 결과를 기다려야 합니다.
- 이름 기본값은 요청에서 이름을 생략한 경우에만 사용합니다.

### 2단계. 접근 방향

- `password`와 cost 값을 `bcrypt.hash`에 전달하고 반환된 문자열을 변수에 저장하세요.
- 사용자 객체에는 원문 비밀번호가 아니라 그 변수를 넣는 기존 흐름을 확인하세요.
- 이름은 요청값을 우선하고 없을 때 학습자용 기본 문자열을 사용하세요.

### 3단계. API 수준

```js
const passwordHash = await bcrypt.hash(/* 원문 비밀번호 */, /* cost */);
const name = req.body.name || /* 기본 이름 문자열 */;
```

## 문제 2. 토큰 payload 완성하기

### 1단계. 개념 환기

- JWT payload는 서버가 토큰 검증 후 사용자 식별에 사용할 최소 정보입니다.
- 비밀번호나 비밀번호 해시는 payload에 넣지 않습니다.

### 2단계. 접근 방향

- `signToken(user)`가 받는 사용자 객체에서 이메일 필드를 읽으세요.
- payload의 기존 키 이름과 검증 후 사용하는 키 이름이 일치하는지 확인하세요.

### 3단계. API 수준

```js
jwt.sign(
  { email: /* user의 이메일 필드 */ },
  /* 비밀키 */,
  /* 만료 옵션 */,
);
```

## 문제 3. Authorization 헤더 읽기

### 1단계. 개념 환기

- 인증 헤더는 `Bearer 토큰값` 형식이라 검증 함수에는 접두사를 뺀 토큰만 전달해야 합니다.
- 헤더가 없을 수도 있으므로 값 접근 전에 그 경우를 고려해야 합니다.

### 2단계. 접근 방향

- `authHeader`에서 정확히 `Bearer ` 부분만 제거하세요.
- 추출 결과가 없을 때 기존 401 흐름으로 들어가는지 확인하세요.

### 3단계. 문자열 API 수준

```js
const token = authHeader?.replace(/* 접두사 */, /* 제거할 문자열 */);
```

## 문제 4. 로그인 검증하기

### 1단계. 개념 환기

- `bcrypt.compare`는 입력한 원문과 저장된 해시가 같은 비밀번호인지 검사합니다.
- 단순 문자열 비교로는 salt가 포함된 bcrypt 해시를 검증할 수 없습니다.

### 2단계. 접근 방향

- 첫 번째 인자에는 로그인 요청의 비밀번호를, 두 번째에는 저장된 해시를 전달하세요.
- 비동기 결과를 기다린 불리언을 기존 실패 분기에서 사용하세요.

### 3단계. API 수준

```js
const isPasswordValid = await bcrypt.compare(
  /* 요청 비밀번호 */,
  /* 저장된 비밀번호 해시 */,
);
```

## 문제 5. 보호된 API 확인하기

### 1단계. 개념 환기

- 인증 미들웨어는 토큰 부재, 유효하지 않은 토큰, 유효한 토큰을 서로 구분합니다.
- 로그인 응답의 토큰은 다음 요청의 헤더에 담아야 합니다.

### 2단계. 접근 방향

- 먼저 헤더 없이 `/me`를 호출해 상태 코드와 body를 기록하세요.
- 회원가입과 로그인을 차례로 실행하고 응답 토큰만 복사하세요.
- 같은 `/me` 요청에 인증 헤더를 추가해 두 결과를 비교하세요.

### 3단계. HTTP 헤더 수준

```http
GET http://localhost:4200/me
Authorization: Bearer <로그인 응답에서 받은 토큰>
```

3단계까지 확인한 뒤에도 막히면 마지막으로 [정답 예시와 비교하세요](./answers.md).
