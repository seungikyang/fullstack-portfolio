# 6단계 로그인 기능

[HTML 목차](../index.html) · [문제 풀기](./problems.md) · [막혔을 때 정답 비교](./answers.md) · [완료 체크](../student-checklist.md)

## 목표

회원가입, 로그인, JWT 인증 미들웨어를 구현하며 웹서비스 인증 흐름을 익힙니다.

## 실행 방법

```bash
cd 06-login-auth
cp .env.example .env
npm install
npm run dev
```

브라우저에서 `http://localhost:4200/health`를 열어 서버 상태를 확인하세요.

[인증 요청 모음](./requests.http)을 VS Code REST Client로 위에서 아래 순서대로 실행하거나, 같은 요청을 Postman·curl로 보내 회원가입·로그인·보호 API 응답을 확인하세요.

막히면 `answers.md`를 보고 다시 직접 고칩니다.

## 완료 기준

- 회원가입 시 비밀번호가 해시로 저장됩니다.
- 로그인 시 비밀번호 검증 후 토큰이 발급됩니다.
- `Authorization: Bearer 토큰` 헤더로 보호된 API에 접근할 수 있습니다.

완료로 표시하기 전 [학습 근거 4종](../student-checklist.md#단계마다-남길-4종-근거)에 실행·요청 명령, 401·409·성공 응답, 해결한 오류, 바꾼 인증 코드 위치를 기록합니다.

## 취업 연결

로그인은 대부분의 웹서비스에 들어가는 핵심 기능입니다. SI/SW 신입은 보안 전문가 수준까지 갈 필요는 없지만, 비밀번호 해시와 토큰 인증의 기본 원리를 반드시 알아야 합니다.

이 단계가 끝나면 “비밀번호를 해시로 저장하고 JWT로 보호된 API를 만들었다”고 설명할 수 있어야 합니다.

## 면접 연습

### 비밀번호를 평문으로 저장하면 안 되는 이유를 설명해보세요.

평문 비밀번호는 DB가 유출되는 순간 사용자 계정이 그대로 탈취됩니다. 많은 사용자가 같은 비밀번호를 여러 서비스에서 재사용하므로 피해가 다른 서비스까지 번질 수 있습니다. 그래서 bcrypt 같은 느린 해시 함수로 저장하고, 로그인 때 입력값을 다시 비교해야 합니다.

### JWT를 요청 헤더에 담아 보내는 이유를 설명해보세요.

JWT는 로그인한 사용자를 증명하는 토큰이므로 보호된 API 요청마다 서버에 전달해야 합니다. 보통 `Authorization: Bearer <token>` 헤더를 사용하면 요청 body나 URL에 토큰을 노출하지 않고 표준적인 방식으로 인증 정보를 보낼 수 있습니다. 서버는 이 토큰의 서명을 검증해 사용자를 식별합니다.

### 401과 409 상태 코드를 언제 쓰는지 설명해보세요.

`401 Unauthorized`는 로그인하지 않았거나 토큰이 없거나 유효하지 않을 때 사용합니다. `409 Conflict`는 요청 자체는 이해했지만 현재 서버 상태와 충돌할 때 사용합니다. 회원가입에서는 이미 등록된 이메일로 가입하려는 경우 409가 적절합니다.
