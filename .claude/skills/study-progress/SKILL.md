# study-progress — 학습 진행 오케스트레이터

루트 워크북 트랙 1~17을 학습할 때 사용하는 워크플로우. `learning-guide` 에이전트가 단계적 힌트 모델로 사용자가 스스로 채우게 한다.

## 언제 트리거되는가

- "공부 시작할게", "오늘 뭐 공부하지?", "다음 트랙 추천"
- "트랙 N의 problems.md 빈칸 채우다가 막혔어"
- "이 코드 채웠는데 봐줘"
- "에러가 났어, 같이 보자"
- "answers.md 보기 전에 힌트만"
- "진도 확인", "학습 점검", "마무리한 트랙 검토"
- "방금 배운 게 8번 포트폴리오 어디에 쓰여?"

이 스킬은 정답을 빠르게 알려주는 도구가 아닙니다. 면접에서 자기 말로 설명할 수 있게 하는 학습 코치입니다.

## 운영 모드: 단일 에이전트

대부분의 학습 세션은 `learning-guide` 한 명이 처리합니다. 다음 경우에만 다른 에이전트를 보조 호출:
- 빈칸을 채운 결과가 8번 포트폴리오의 동일 영역과 다르다 → `qa-integration-checker` 협업
- 트랙 12(테스트) 학습 → `test-coverage-analyst` 자문
- 트랙 11(Spring) 학습 후 SI 다리 정리 → `si-job-fit-coach` 자문

기본 호출은 `Agent` 도구로 `learning-guide` 직접 호출, `model: "opus"` 명시.

## Phase 0: 컨텍스트 확인

진입 시 다음을 확인:

1. 사용자가 어느 트랙·어떤 시점인지
2. `_workspace/study/`에 이전 세션 요약이 있는가?
   - 있다면 가장 최근 세션을 먼저 읽어 이어서 진행
   - 없다면 신규 학습 시작
3. `npm run progress`로 전체 빈칸 현황 한번 확인 (선택)

작업 디렉토리: 저장소 루트 (학습은 트랙별로 다른 폴더에서 진행)

## Phase 1: 학습 목표 정렬

사용자 요청에 따라 세션 유형을 결정:

| 세션 유형 | 행동 |
|----------|------|
| **다음 트랙 결정** | 학습 진행 상태 + 우선순위 권장 (career-prep-strategist 자문 가능) |
| **현재 트랙 진행 중 막힘** | 4단계 힌트 모델로 진행 |
| **채운 코드 검토** | 검토 체크리스트로 평가 |
| **에러 디버깅** | 에러 메시지 함께 읽기 → 가설 묻기 → 단계적 유도 |
| **트랙 마무리 회고** | 무엇을 배웠는지 한 문단 + 8번 포트폴리오 연결 다리 + 면접 답안 후보 |

## Phase 2: 세션 진행 (learning-guide 호출)

`learning-guide` 에이전트에게 다음을 전달:
- 세션 유형
- 현재 트랙·파일·라인
- 이전 세션 요약 (있다면)
- 사용자 발화 원문

`learning-guide`는 4단계 힌트 모델로 진행하며 사용자와 인터랙티브 대화한다.

## Phase 3: 세션 요약 저장

세션 종료 시(사용자가 "오늘은 여기까지"라고 하거나 한 단위 학습이 끝나면):

`_workspace/study/{YYYY-MM-DD}_{트랙}_session.md`에 저장:
```markdown
# 학습 세션: 2026-05-26 트랙 06 Auth

## 작업 내용
- problems.md 빈칸 #3 (bcrypt 해시) 채움 → 통과
- 에러 1건 디버깅: "Cannot read properties of undefined (reading 'compare')" → import 빠짐을 사용자가 직접 발견

## 면접 답안 후보
- "bcrypt를 쓴 이유"에 대한 답안 한 단락 (코드 근거: `auth.js:24`)

## 다음 액션
- 트랙 06의 JWT 발급 빈칸 진행 (next)
- 8번 포트폴리오 `server/auth.js`와 비교해 다른 점 확인 권장
```

## Phase 4: 다리(bridge) 안내

트랙 학습 마무리 시점에 항상 다음을 안내:
- 방금 배운 것이 8번 포트폴리오의 어디에 쓰였는지 1~2줄
- 이 학습이 어떤 면접 질문에 활용될 수 있는지 1줄
- 다음 자연스러운 학습 단계 1줄

## Phase 5: 피드백 수집

세션 종료 시 한 번 묻는다:
- "오늘 학습이 어땠어요? 힌트 강도가 맞았나요?"

피드백은 `_workspace/study/feedback.md`에 누적 기록.

## 데이터 전달 규칙

- 모든 중간 산출물: `_workspace/study/` (루트 기준)
- 한 트랙당 여러 세션이 누적될 수 있음 (날짜 prefix로 구분)
- 트랙 완주 시 `_workspace/study/{트랙}_complete.md` 한 페이지 회고 작성

## 에러 핸들링

| 상황 | 처리 |
|------|------|
| `npm run progress` 실행 실패 | grep으로 빈칸 추정, 사유 보고 |
| `answers.md`가 없는 트랙 | "정답 파일이 없습니다, 검증은 코드 실행으로만" 안내 |
| 사용자가 답을 강하게 요구 | 1회 노출 + "자기 말로 다시 설명" 요청 + 세션 요약에 표시 |
| 학습 세션 도중 중단 | 즉시 세션 요약 임시 저장 (다음에 이어서 가능) |

## 다른 허브와의 관계

이 스킬은 **공부(Phase A)** 허브입니다. 사용자가 "포트폴리오 다듬기"로 넘어가고 싶으면 → `portfolio-improvement` 스킬로 인계. "이력서 작성"이라면 → `job-hunt-preparation` 스킬로 인계. 인계 시 학습 세션 요약(`_workspace/study/`)을 그쪽이 참조할 수 있도록 한다.

## 테스트 시나리오

### 정상 흐름: 트랙 막힘
1. 사용자: "06 트랙에서 bcrypt.hash 빈칸 어떻게 채워?"
2. Phase 0: 신규 세션 시작
3. Phase 1: 세션 유형 = "현재 트랙 진행 중 막힘"
4. Phase 2: learning-guide 호출 → 4단계 힌트 모델로 진행
5. 사용자가 정답 채움 → 검토 통과
6. Phase 3~4: 세션 요약 + 8번 포트폴리오 연결 다리 안내
7. Phase 5: 피드백 수집

### 에러 흐름: 답안 강 요구
1. 사용자: "그냥 정답 보여줘"
2. learning-guide: "1번만 보여드리되, 자기 말로 다시 설명 부탁드릴게요"
3. 정답 노출 후 사용자 설명 받기 → 세션 요약에 "답안 즉공개 발생" 표시
4. 다음 세션에서 힌트 모델 강도 한 단계 높게 시작
