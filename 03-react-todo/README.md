## 목표

컴포넌트, props, state를 사용해 Todo 목록 앱을 만듭니다.

## 기술을 쓰는 이유와 동작 흐름

처음 보는 용어는 [전체 기술 안내서](../technology-guide.md)와 함께 읽으세요. 아래 흐름은 실습을 이해하기 위한 안내이며, 빈칸과 완료 체크는 직접 진행합니다.

| 기술 | 무엇이고, 왜 필요한가요? | 이 실습에서는 어떻게 쓰나요? |
| --- | --- | --- |
| React와 컴포넌트 | React는 화면을 작은 함수 단위인 컴포넌트로 구성하는 도구입니다. 화면의 각 부분을 나눠 이해하고 관리하게 합니다. | [App.jsx](./src/App.jsx)는 전체 목록, [TodoItem.jsx](./src/components/TodoItem.jsx)는 할 일 하나를 담당합니다. |
| state·props | state는 컴포넌트가 기억하는 변경 가능한 값이고, props는 부모가 자식에 전달하는 값입니다. 데이터의 주인과 전달 방향을 분명하게 합니다. | `App`이 목록을 보관하고 `TodoItem`에 항목과 동작 함수를 전달합니다. |
| JSX | JavaScript 안에 화면 구조를 표현하는 문법입니다. 데이터와 그 데이터가 보일 위치를 함께 읽을 수 있습니다. | 두 컴포넌트의 반환 부분에서 목록·버튼을 표현합니다. |
| Vite | 개발 서버와 배포용 파일 생성을 도와주는 도구입니다. 브라우저가 실행할 수 있도록 JSX 등을 변환합니다. | [package.json](./package.json)의 `dev`와 `build` 명령이 Vite를 실행합니다. |

**완료 버튼의 처리 순서:** 자식의 클릭 이벤트 → 부모가 전달한 함수 실행 → 부모의 목록 state 갱신 → 컴포넌트가 새 상태로 화면을 계산 → React가 필요한 DOM 변경을 반영. 모든 DOM을 매번 지우는 방식으로 이해하지 않아도 됩니다.

**직접 관찰하기:** 완료를 누를 때 할 일 한 개의 표시와 남은 개수가 함께 맞는지 확인하세요. 화면 함수가 실행되는 것과 서버에 데이터를 저장하는 것은 별개입니다. 이 실습에는 저장 API가 없으며, Career Hub에서는 같은 상태 흐름에 API 요청이 추가됩니다.

## 실행 방법

```bash
cd 03-react-todo
npm install
npm run dev
```

## 학습 순서

1. `src/App.jsx`에서 state가 어디에 있는지 찾습니다.
2. `src/components/TodoItem.jsx`에서 props가 어떻게 전달되는지 확인합니다.
3. `problems.md`의 순서대로 빈칸을 채웁니다.
4. 브라우저에서 할 일 추가와 완료 전환이 되는지 확인합니다.
5. `npm run build`로 production 빌드가 통과하는지 확인합니다.
6. 막히면 `hints.md`의 1단계부터 3단계까지 필요한 만큼만 봅니다.
7. 그래도 해결되지 않을 때만 `answers.md`와 비교하고 다시 직접 고칩니다.

## 완료 기준

- 입력창에 적은 할 일이 목록에 추가됩니다.
- 각 Todo의 완료 상태를 바꿀 수 있습니다.
- 남은 할 일 개수가 실제 목록과 일치합니다.
- `npm run build`가 오류 없이 통과합니다.

완료로 표시하기 전 [학습 근거 4종](../student-checklist.md#단계마다-남길-4종-근거)에 실행 명령, UI 관찰 결과, 해결한 오류, 바꾼 컴포넌트 위치를 기록합니다.

## 취업 연결

React는 SI/SW 웹 프로젝트에서도 많이 쓰이는 프론트엔드 기술입니다. 신입에게는 거대한 상태관리보다 컴포넌트 분리, props 전달, state 변경 흐름을 정확히 이해하는 것이 더 중요합니다.

이 단계가 끝나면 “Todo 앱을 컴포넌트로 나누고 state로 화면을 갱신했다”고 설명할 수 있어야 합니다.
