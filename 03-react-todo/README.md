## 목표

컴포넌트, props, state를 사용해 Todo 목록 앱을 만듭니다.

## 실행 방법

```bash
cd 03-react-todo
npm install
npm run dev
```

## 학습 순서

1. `src/App.jsx`에서 state가 어디에 있는지 찾습니다.
2. `src/components/TodoItem.jsx`에서 props가 어떻게 전달되는지 확인합니다.
3. `problems.md`의 순서대로 빈칸을 채웁니다.
4. 브라우저에서 할 일 추가와 완료 전환이 되는지 확인합니다.
5. `npm run build`로 production 빌드가 통과하는지 확인합니다.
6. 막히면 `answers.md`를 보고 다시 직접 고칩니다.

## 완료 기준

- 입력창에 적은 할 일이 목록에 추가됩니다.
- 각 Todo의 완료 상태를 바꿀 수 있습니다.
- 남은 할 일 개수가 실제 목록과 일치합니다.
- `npm run build`가 오류 없이 통과합니다.

완료로 표시하기 전 [학습 근거 4종](../student-checklist.md#단계마다-남길-4종-근거)에 실행 명령, UI 관찰 결과, 해결한 오류, 바꾼 컴포넌트 위치를 기록합니다.

## 취업 연결

React는 SI/SW 웹 프로젝트에서도 많이 쓰이는 프론트엔드 기술입니다. 신입에게는 거대한 상태관리보다 컴포넌트 분리, props 전달, state 변경 흐름을 정확히 이해하는 것이 더 중요합니다.

이 단계가 끝나면 “Todo 앱을 컴포넌트로 나누고 state로 화면을 갱신했다”고 설명할 수 있어야 합니다.

## 면접 연습

### state를 직접 수정하지 않고 `setTodos`를 쓰는 이유를 설명해보세요.

React는 state 변경을 감지해야 화면을 다시 렌더링합니다. 배열을 직접 수정하면 React가 변경을 안정적으로 추적하기 어렵고, 이전 상태를 예측하기도 힘듭니다. `setTodos`로 새 배열을 만들어 전달하면 React가 변경을 인식하고 화면을 올바르게 갱신합니다.

### props가 부모에서 자식으로 전달되는 흐름을 설명해보세요.

부모 컴포넌트가 데이터를 가지고 있고, 자식 컴포넌트는 그 데이터를 props로 받아 화면에 표시하거나 이벤트를 호출합니다. 예를 들어 `App`이 todo 목록을 state로 관리하고 `TodoItem`에 todo 객체와 클릭 함수를 전달합니다. 이 구조는 데이터의 출처를 부모에 두고 화면 조각은 자식으로 분리하기 때문에 유지보수가 쉬워집니다.

### `key` props가 필요한 이유를 설명해보세요.

React가 목록을 렌더링할 때 각 항목을 구분하려면 안정적인 식별자가 필요합니다. `key`가 있어야 어떤 항목이 추가, 삭제, 변경됐는지 효율적으로 비교할 수 있습니다. `key`가 부정확하면 잘못된 항목이 재사용되어 화면 상태가 꼬일 수 있습니다.
