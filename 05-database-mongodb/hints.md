## 문제 1. 모델 완성하고 이해하기

### 1단계. 개념 환기

- Mongoose 스키마의 `default`는 입력이 생략됐을 때 저장할 값을 정합니다.
- `required`, `trim`, `timestamps`는 각각 필수값, 문자열 정리, 시간 필드 생성을 담당합니다.

### 2단계. 접근 방향

- `author` 필드 설정에서 기본값 자리에 익명 사용자를 나타낼 문자열을 넣으세요.
- 코드를 채운 뒤 생성 요청에서 작성자를 빼고 실제 저장 결과를 확인하세요.
- 자동으로 생긴 필드는 DB 응답의 키 이름을 보고 설명하세요.

### 3단계. 스키마 옵션 수준

```js
author: {
  type: String,
  default: /* 작성자가 없을 때 쓸 문자열 */,
}
```

## 문제 2. 데이터 생성하기

### 1단계. 개념 환기

- `Post.create`는 전달한 객체를 MongoDB에 저장하고 생성된 문서를 반환합니다.
- 요청 body 필드와 모델 필드 이름이 같아야 원하는 값이 저장됩니다.

### 2단계. 접근 방향

- `title`, `content`, `author`를 각각 `req.body`에서 읽으세요.
- 작성자만 생략 가능한 값으로 보고 대체값을 두세요.
- 생성 후 반환된 문서를 응답하는 기존 흐름은 유지하세요.

### 3단계. Mongoose API 수준

```js
const post = await Post.create({
  title: req.body./* 제목 필드 */,
  content: req.body./* 내용 필드 */,
  author: req.body./* 작성자 필드 */ || /* 기본 작성자 */,
});
```

## 문제 3. 데이터 수정하기

### 1단계. 개념 환기

- Mongoose 문서는 필드를 바꾼 뒤 `save`해야 변경이 DB에 반영됩니다.
- 일부 입력이 없을 때 기존 문서 값을 보존해야 합니다.

### 2단계. 접근 방향

- 기존 조회 코드가 가져온 `post`의 세 필드를 하나씩 갱신하세요.
- 각 필드에 요청값과 기존값의 우선순위를 적용하세요.
- 마지막 저장과 응답 코드는 그대로 사용하세요.

### 3단계. 문서 갱신 수준

```js
post.title = req.body.title || /* 기존 title */;
post.content = req.body.content || /* 기존 content */;
post.author = req.body.author || /* 기존 author */;

await post.save();
```

## 문제 4. 데이터 삭제하기

### 1단계. 개념 환기

- MongoDB의 `_id`는 문자열 형태로 URL을 통해 전달될 수 있습니다.
- `findByIdAndDelete`는 id로 문서를 찾아 삭제하는 Mongoose 메서드입니다.

### 2단계. 접근 방향

- 삭제 메서드에 고정 문자열이 아니라 현재 요청의 URL id를 전달하세요.
- 삭제 결과가 없을 때의 404와 성공 응답은 기존 코드를 유지하세요.

### 3단계. Mongoose API 수준

```js
const deletedPost = await Post.findByIdAndDelete(/* URL 파라미터 id */);
```

## 문제 5. 오류 읽기

### 1단계. 개념 환기

- 연결 오류에는 호스트, 포트, DNS, 인증 같은 원인 단서가 포함됩니다.
- 가장 바깥 요약만 보지 말고 첫 원인 메시지와 오류 코드를 함께 봐야 합니다.

### 2단계. 접근 방향

- 정상 연결 주소를 따로 복사해 둔 뒤 한 부분만 바꾸세요.
- 실행 명령, 첫 오류 줄, 실제로 바꾼 주소 부분을 기록하세요.
- 주소를 복원하고 다시 실행해 원인 가설이 맞았는지 확인하세요.

### 3단계. 확인 지점

```text
실행 명령 → 오류 이름/코드 → 연결 대상 host:port → 수정한 값 → 복원 후 결과
```

3단계까지 확인한 뒤에도 막히면 마지막으로 [정답 예시와 비교하세요](./answers.md).
