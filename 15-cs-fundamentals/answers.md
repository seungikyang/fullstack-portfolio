# CS 기초 21문제 정답·해설

[문제](./problems.md) · [단계별 힌트](./hints.md) · [완료 체크](../student-checklist.md) · [다음 단계](../16-security/README.md)

문제의 보기를 먼저 선택한 뒤 확인하세요.

## N1. TCP와 UDP의 차이

**정답: 1번 — TCP는 바이트 스트림의 순서와 재전송을 제공하고 UDP는 이를 자체 보장하지 않는다.**

TCP는 연결 기반 신뢰성 전송을 제공하며 UDP는 데이터그램 전달 방식입니다. 실제 지연은 환경과 구현에 따라 달라집니다.

## N2. 3-way handshake가 필요한 이유

**정답: 2번 — 양쪽의 초기 시퀀스 번호와 연결 의사를 확인한다.**

SYN, SYN+ACK, ACK로 TCP 연결을 설정합니다. TLS와 DNS는 별도의 역할입니다.

## N3. HTTP와 HTTPS의 차이

**정답: 3번 — HTTPS는 TLS로 전송 구간의 기밀성·무결성과 서버 인증을 제공한다.**

HTTPS는 HTTP 통신을 TLS로 보호합니다. 접근 제어와 애플리케이션 취약점 방어는 별도로 필요합니다.

## N4. 캐시·연결 재사용 없는 HTTP/1.1·HTTP/2 HTTPS 요청의 흐름

**정답: 4번 — DNS 조회 → TCP 연결 → TLS 연결 → HTTP 요청·응답 → 문서 파싱과 렌더링**

캐시와 기존 연결을 사용하지 않는 HTTP/1.1 또는 HTTP/2 연결을 가정합니다. HTTP/3는 QUIC를 사용하므로 전송 흐름이 다릅니다.

## N5. 쿠키·세션·토큰의 관계

**정답: 1번 — 쿠키는 브라우저 저장·전송 수단이고, 세션은 서버 상태를 식별하며 JWT는 서명된 클레임을 담는다.**

쿠키에는 세션 ID나 토큰을 담을 수 있습니다. 일반적인 서명 JWT는 내용을 암호화하지 않으며 폐기 정책이 별도로 필요합니다.

## N6. CORS와 같은 출처 정책

**정답: 2번 — 서버의 허용 헤더를 보고 브라우저가 다른 출처 응답의 읽기 허용 여부를 판단한다.**

출처는 scheme, host, port 조합입니다. CORS는 브라우저 정책이며 인증이나 권한 검사를 대신하지 않습니다.

## O1. 프로세스와 스레드

**정답: 3번 — 프로세스는 주소 공간을 분리하고 같은 프로세스의 스레드는 메모리를 공유한다.**

스레드의 공유 메모리는 통신에 유리하지만 동기화가 필요합니다. 프로세스 간에는 IPC 등을 이용합니다.

## O2. race condition과 deadlock

**정답: 4번 — race condition은 실행 순서에 따라 결과가 달라지고 deadlock은 자원을 서로 기다려 진행하지 못한다.**

공유 자원의 변경 순서와 자원 대기 관계를 구분해야 합니다. 락 순서 통일이나 원자적 연산이 상황에 따라 필요합니다.

## O3. 스택과 힙

**정답: 1번 — 호출 스택은 함수 실행 흐름을 관리하고 힙은 동적 객체 할당에 사용한다.**

너무 깊은 재귀는 스택 한도를 넘을 수 있습니다. 힙 객체는 언어 런타임의 메모리 관리 규칙에 따라 해제됩니다.

## O4. Node.js 비동기 I/O와 이벤트 루프

**정답: 2번 — 비동기 I/O를 기다리는 동안 다른 콜백을 처리할 수 있지만 긴 CPU 작업은 이벤트 루프를 막을 수 있다.**

await는 해당 async 함수의 진행을 유예합니다. 긴 동기 계산이나 동기 I/O는 이벤트 루프 처리 지연을 만들 수 있습니다.

## O5. 가상 메모리와 thrashing

**정답: 3번 — 가상 주소를 물리 메모리에 매핑하며 페이지 교체가 과도하면 성능이 급격히 떨어질 수 있다.**

주소 공간 추상화와 실제 메모리 용량은 다릅니다. 잦은 페이지 입출력은 유용한 계산 시간을 줄일 수 있습니다.

## D1. ACID와 송금

**정답: 4번 — 원자성은 출금·입금을 모두 반영하거나 모두 취소하고 영속성은 커밋된 결과의 보존을 뜻한다.**

ACID는 원자성, 일관성, 격리성, 영속성입니다. 일관성은 트랜잭션 전후 정의된 무결성 규칙의 유지를 뜻합니다.

## D2. SQL 표준의 트랜잭션 격리 수준

**정답: 1번 — READ COMMITTED는 dirty read를 막지만 non-repeatable read는 허용할 수 있다.**

SQL 표준의 최소 보장과 DB 구현을 구분합니다. PostgreSQL의 REPEATABLE READ처럼 표준보다 강한 보장을 제공할 수 있습니다.

## D3. 1NF·2NF·3NF 정규화

**정답: 2번 — 원자값 → 부분 함수 종속 제거 → 이행 함수 종속 제거 순서로 진행한다.**

2NF와 3NF는 함수 종속 관계를 기준으로 분리합니다. 정규화는 삽입·수정·삭제 이상을 줄이려는 설계 방법입니다.

## D4. B+Tree와 해시 인덱스

**정답: 3번 — B+Tree는 정렬된 범위 검색에 적합하고 해시 인덱스는 보통 등가 검색에 적합하다.**

인덱스의 종류와 쿼리 조건을 함께 봐야 합니다. 인덱스 유지 비용 때문에 읽기 이점과 쓰기 비용의 균형이 필요합니다.

## D5. RDBMS와 NoSQL의 선택

**정답: 4번 — 데이터 모양·조회 패턴·트랜잭션·확장 요구를 비교해 선택한다.**

NoSQL은 하나의 공통 기능 목록이 아닙니다. 제품별 보장과 요구 사항을 비교해야 하며 MongoDB도 트랜잭션을 지원합니다.

## S1. 배열과 연결 리스트의 접근 비용

**정답: 1번 — 배열의 인덱스 접근은 보통 O(1), 단일 연결 리스트의 i번째 접근은 O(n)이다.**

연결 리스트의 삽입·삭제가 O(1)이라는 설명에는 필요한 노드나 이전 노드를 이미 알고 있다는 조건이 붙습니다.

## S2. 해시 테이블의 평균 O(1)

**정답: 2번 — 해시가 고르게 분산되면 평균 조회 비용이 작지만 충돌이 집중되면 느려질 수 있다.**

체이닝과 오픈 어드레싱으로 충돌을 처리합니다. 평균 복잡도는 분산·부하율 가정에 의존하며 최악 성능은 구현별로 다릅니다.

## S3. 스택과 큐의 실제 쓰임

**정답: 3번 — 스택은 LIFO로 호출·되돌리기에, 큐는 FIFO로 작업 대기에 사용할 수 있다.**

LIFO는 후입선출, FIFO는 선입선출입니다. 순서 규칙을 실제 호출 스택이나 작업 큐와 연결해 이해합니다.

## S4. 이진 탐색 트리의 최악 성능

**정답: 4번 — 한쪽으로 치우친 트리는 검색이 O(n)이 될 수 있고 균형 트리는 높이를 O(log n)으로 관리한다.**

검색 비용은 트리 높이에 영향을 받습니다. AVL·Red-Black 등의 균형 조건이 최악 높이를 제한합니다.

## S5. Big-O와 전체 스캔

**정답: 1번 — n개 행을 하나씩 확인하는 선형 스캔의 작업량은 O(n)이다.**

Big-O는 입력 크기에 따른 증가율을 표현합니다. 실제 시간은 I/O, 캐시, 하드웨어와 구현에도 영향을 받습니다.
