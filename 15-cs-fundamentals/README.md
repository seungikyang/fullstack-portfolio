# 15단계 CS 기초 (네트워크 · OS · DB 이론 · 자료구조)

[HTML 목차](../index.html) · 학습 흐름. [문제 풀기](./problems.md) → [단계별 힌트](./hints.md) → [정답 비교](./answers.md) → [완료 체크](../student-checklist.md)

## 목표

신입 기술 면접에서 자주 다루는 CS 기초 질문을 자기 말과 자기 코드 근거로 설명하는 연습을 합니다. 평가 비중은 회사와 직무마다 다르므로 암기보다 실제 프로젝트와의 연결을 우선합니다.

이 단계는 **4지선다 선택 → 채점 → 정답·해설 확인 → 오답 복습** 흐름입니다. 네트워크 6문제, OS 5문제, DB 이론 5문제, 자료구조 5문제로 구성됩니다.

## 기술을 쓰는 이유와 동작 흐름

처음 보는 용어는 [전체 기술 안내서](../technology-guide.md)와 함께 읽으세요. 아래 흐름은 실습을 이해하기 위한 안내이며, 빈칸과 완료 체크는 직접 진행합니다.

CS는 컴퓨터 과학의 기초 개념입니다. 이 단계는 새 실행 도구를 설치하기보다 앞서 실행한 코드의 동작 이유를 설명하는 단계입니다. [문제](./problems.md)에서 네 보기 중 알맞은 답 하나를 고릅니다.

| 개념 | 무엇이고, 왜 필요한가요? | 어디에 연결해서 보나요? |
| --- | --- | --- |
| 네트워크·HTTP | 네트워크는 컴퓨터 사이의 통신이고, HTTP는 웹 요청·응답의 약속입니다. 화면 오류가 통신의 어느 지점에서 생겼는지 나누어 생각하게 합니다. | [7단계 화면 요청](../07-project-deploy/public/app.js)과 [서버](../07-project-deploy/src/server.js)를 연결합니다. |
| 운영체제·프로세스 | 운영체제는 CPU·메모리 같은 자원을 관리하고, 프로세스는 실행 중인 프로그램입니다. 서버 실행·종료와 데이터 수명을 이해하는 데 필요합니다. | [4단계 서버](../04-node-board-api/src/server.js)의 메모리 배열과 재시작 결과를 연결합니다. |
| DB·트랜잭션 | DB는 데이터를 관리하는 저장 시스템이고, 트랜잭션은 작업을 한 묶음으로 확정·취소하는 단위입니다. 여러 변경이 일부만 남는 문제를 설명합니다. | [10단계 실험](../10-sql-oracle/starter/06-transaction.sql)의 관찰과 연결합니다. |
| 자료구조·복잡도 | 자료구조는 데이터를 담고 찾는 방식이고, 복잡도는 데이터가 늘 때 작업량이나 공간이 얼마나 늘어나는지 나타내는 척도입니다. 선택한 저장·검색 방식의 비용을 설명합니다. | 4단계의 게시글 배열 검색에서 확인해야 하는 항목 수를 생각합니다. |

**한 요청을 설명하는 순서:** 화면 코드가 요청 생성 → 통신으로 서버에 전달 → 서버 프로세스가 처리 → 메모리 또는 DB에서 데이터 확인 → 응답 → 화면 갱신. 지금 설명하는 대상이 브라우저·서버·DB 중 어디인지 먼저 구분하세요.

**직접 관찰하기:** 한 개념마다 연결한 파일과 실행 결과를 한 가지 적으세요. 배열을 검색하는 코드만 보고 실제 응답 시간이 얼마라고 단정하지 않습니다. 이 구분은 17단계에서 배운 원리와 직접 확인한 경험을 구별해 설명하는 연습으로 이어집니다.

### R15-01. TCP와 UDP의 차이를 설명해보세요.

TCP와 UDP의 차이를 설명해보세요. — 알맞은 설명 또는 답변 방식을 고르세요.

1. TCP는 바이트 스트림의 순서와 재전송을 제공하고 UDP는 이를 자체 보장하지 않는다.
2. UDP만 연결 설정을 하고 TCP는 비연결형이다.
3. TCP와 UDP 모두 손실된 데이터를 반드시 재전송한다.
4. UDP를 쓰면 애플리케이션에서 신뢰성을 추가할 수 없다.

### R15-02. 프로세스와 스레드는 무엇이 다른가요?

프로세스와 스레드는 무엇이 다른가요? — 알맞은 설명 또는 답변 방식을 고르세요.

1. 서로 다른 프로세스의 모든 변수는 자동으로 공유된다.
2. 프로세스는 주소 공간을 분리하고 같은 프로세스의 스레드는 메모리를 공유한다.
3. 스레드는 항상 별도 프로세스의 주소 공간을 가진다.
4. 스레드끼리 공유 메모리를 쓰면 동기화가 필요 없다.

<summary>정답·해설 확인</summary>

**정답: 2번**

스레드의 공유 메모리는 통신에 유리하지만 동기화가 필요합니다. 프로세스 간에는 IPC 등을 이용합니다.

### R15-04. HashMap의 평균 시간 복잡도가 O(1)인 이유는 무엇인가요?

HashMap의 평균 시간 복잡도가 O(1)인 이유는 무엇인가요? — 알맞은 설명 또는 답변 방식을 고르세요.

1. 해시 함수는 서로 다른 키에 절대로 같은 값을 반환하지 않는다.
2. 충돌이 많아도 모든 구현은 최악 O(1)을 보장한다.
3. 체이닝은 충돌한 키를 무조건 삭제하는 방식이다.
4. 해시가 고르게 분산되면 평균 조회 비용이 작지만 충돌이 집중되면 느려질 수 있다.

<summary>정답·해설 확인</summary>

**정답: 4번**

체이닝과 오픈 어드레싱으로 충돌을 처리합니다. 평균 복잡도는 분산·부하율 가정에 의존하며 최악 성능은 구현별로 다릅니다.

</details>

## 학습 영역

### 네트워크

- OSI 7계층과 TCP/IP 4계층.
- TCP vs UDP. 3-way handshake.
- HTTP 메서드와 상태 코드 (이미 4단계에서 다룬 내용 심화).
- HTTPS와 TLS. 인증서.
- DNS와 도메인 해석 흐름.
- 쿠키, 세션, 토큰의 차이.

### 운영체제

- 프로세스 vs 스레드.
- 멀티스레드의 동시성과 동기화. race condition, deadlock.
- 메모리 구조. stack, heap, code, data.
- CPU 스케줄링. 선점형 vs 비선점형.
- 가상 메모리와 페이지 교체.

### DB 이론

- ACID의 네 가지 속성.
- 트랜잭션 격리 수준 (READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE).
- 정규화 1NF, 2NF, 3NF.
- 인덱스의 구조 (B+Tree).
- NoSQL이 등장한 이유와 RDBMS와의 트레이드오프.

### 자료구조

- 배열, 연결 리스트, 스택, 큐의 시간 복잡도.
- 해시 테이블의 충돌과 해결법.
- 이진 탐색 트리와 균형 트리(AVL, Red-Black).
- 그래프 표현 (인접 행렬, 인접 리스트).
- 시간/공간 복잡도(Big-O) 개념.

## 면접에서 답할 때 주의

- "들어본 적 있다"가 아니라 **자기 예시**로 설명하세요. 예시. "TCP는 4단계 게시판 API의 HTTP 요청에서 쓰고, UDP는 게임 패킷이나 실시간 음성처럼 손실보다 지연이 더 치명적인 곳에 씁니다."
