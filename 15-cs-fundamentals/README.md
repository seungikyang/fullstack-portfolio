## 취업 연결

SI/SW 면접에서 CS 기초는 다음 형태로 자주 나옵니다.

- "TCP와 UDP의 차이를 설명해보세요."
- "프로세스와 스레드는 무엇이 다른가요?"
- "트랜잭션 격리 수준 네 가지를 차이와 함께 설명해보세요."
- "HashMap의 평균 시간 복잡도가 O(1)인 이유는 무엇인가요?"

이 단계가 끝나면 위 같은 질문에 30초~1분 안에 답할 수 있어야 합니다.

## 대표 질문 답변 예시

### TCP와 UDP의 차이를 설명해보세요.

TCP는 연결을 맺고 순서, 재전송, 흐름 제어를 통해 신뢰성 있는 전송을 제공합니다. HTTP API처럼 데이터가 정확히 도착해야 하는 경우에 적합합니다. UDP는 연결 설정과 재전송 부담이 적어 빠르지만 손실 가능성이 있으며, 실시간 음성, 게임, 스트리밍처럼 지연이 더 중요한 곳에서 사용됩니다.

### 프로세스와 스레드는 무엇이 다른가요?

프로세스는 실행 중인 프로그램의 독립된 실행 단위이고, 각자 메모리 공간을 가집니다. 스레드는 프로세스 안에서 실행되는 더 작은 작업 단위이며 같은 프로세스의 메모리를 공유합니다. 스레드는 생성과 전환 비용이 비교적 낮지만 공유 자원 때문에 race condition 같은 동기화 문제가 생길 수 있습니다.

### 트랜잭션 격리 수준 네 가지를 차이와 함께 설명해보세요.

READ UNCOMMITTED는 커밋되지 않은 데이터까지 읽을 수 있어 dirty read가 발생할 수 있습니다. READ COMMITTED는 커밋된 데이터만 읽지만 같은 트랜잭션 안에서 다시 읽을 때 값이 달라질 수 있습니다. REPEATABLE READ는 같은 행을 반복 조회해도 같은 값을 보장하지만 phantom read 가능성이 남을 수 있고, SERIALIZABLE은 가장 강한 격리로 동시성을 줄이는 대신 정합성을 가장 강하게 보장합니다.

### HashMap의 평균 시간 복잡도가 O(1)인 이유는 무엇인가요?

HashMap은 키를 해시 함수로 배열의 인덱스에 가깝게 변환해 바로 접근합니다. 충돌이 적고 해시가 고르게 분포하면 검색, 삽입, 삭제가 평균적으로 상수 시간에 가깝습니다. 다만 충돌이 많거나 해시 품질이 나쁘면 성능이 떨어질 수 있어 충돌 처리와 리사이징이 중요합니다.

## 학습 영역

### 네트워크

- OSI 7계층과 TCP/IP 4계층.
- TCP vs UDP. 3-way handshake.
- HTTP 메서드와 상태 코드 (이미 4단계에서 다룬 내용 심화).
- HTTPS와 TLS. 인증서.
- DNS와 도메인 해석 흐름.
- 쿠키, 세션, 토큰의 차이.

### 운영체제

- 프로세스 vs 스레드.
- 멀티스레드의 동시성과 동기화. race condition, deadlock.
- 메모리 구조. stack, heap, code, data.
- CPU 스케줄링. 선점형 vs 비선점형.
- 가상 메모리와 페이지 교체.

### DB 이론

- ACID의 네 가지 속성.
- 트랜잭션 격리 수준 (READ UNCOMMITTED, READ COMMITTED, REPEATABLE READ, SERIALIZABLE).
- 정규화 1NF, 2NF, 3NF.
- 인덱스의 구조 (B+Tree).
- NoSQL이 등장한 이유와 RDBMS와의 트레이드오프.

### 자료구조

- 배열, 연결 리스트, 스택, 큐의 시간 복잡도.
- 해시 테이블의 충돌과 해결법.
- 이진 탐색 트리와 균형 트리(AVL, Red-Black).
- 그래프 표현 (인접 행렬, 인접 리스트).
- 시간/공간 복잡도(Big-O) 개념.

## 면접에서 답할 때 주의

- "들어본 적 있다"가 아니라 **자기 예시**로 설명하세요. 예시. "TCP는 4단계 게시판 API의 HTTP 요청에서 쓰고, UDP는 게임 패킷이나 실시간 음성처럼 손실보다 지연이 더 치명적인 곳에 씁니다."
- 모르는 건 모른다고 인정하세요. 거짓 자신감은 더 큰 감점입니다.
- 정의 → 차이점 → 예시 순서로 1분 안에 끝내는 것이 모범 답안 패턴입니다.
