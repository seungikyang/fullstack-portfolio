# 15단계 단계별 힌트

[단계 설명](./README.md) · [문제로 돌아가기](./problems.md) · [완료 체크](../student-checklist.md)

한 번에 모두 읽지 말고, 막힌 영역의 1단계부터 차례로 확인하세요. 각 키워드는 완성 답안이 아니라 자기 답안을 점검하는 기준입니다.

## 네트워크 문제 묶음 N1~N6

### 1단계. 개념 환기

- 네트워크 답변은 연결 방식, 신뢰성, 보안 경계, 저장 위치처럼 비교 축을 먼저 정하면 정리하기 쉽습니다.
- 프로토콜 이름만 나열하지 말고 요청이 이동하는 순서와 실패했을 때의 동작을 함께 떠올리세요.
- 6단계 인증 요청과 브라우저의 출처 정책을 실제 코드 근거로 연결하세요.

### 2단계. 접근 방향

- N1, N3, N5는 비교표를 먼저 만들고 사용 예시를 마지막에 붙이세요.
- N2와 N4는 시간 순서대로 화살표를 그린 뒤 각 단계의 목적을 한 문장씩 적으세요.
- N6는 같은 출처 정책이 막는 주체와 CORS 응답 헤더를 확인하는 주체를 구분하세요.

### 3단계. 답변 키워드와 틀

| 문제 | 답에 포함할 키워드                                                         |
| ---- | -------------------------------------------------------------------------- |
| N1   | 연결 설정 여부, 전달·순서 보장, 재전송, 지연, 사용 사례                    |
| N2   | `SYN`, `SYN+ACK`, `ACK`, 양방향 송수신 가능 확인                           |
| N3   | TLS, 암호화, 서버 인증서, 무결성, HTTP 메시지 보호                         |
| N4   | DNS → 연결/TLS → HTTP 요청·응답 → 브라우저 파싱·렌더링                     |
| N5   | 브라우저 저장, 서버 저장, 전달 방식, 탈취·CSRF 고려, 확장성                |
| N6   | origin 구성 요소, Same-Origin Policy, 허용 origin 응답 헤더, 브라우저 검사 |

```text
[개념 정의]입니다. [비교 기준]에서는 [차이]가 있습니다.
제가 작성한 [트랙/파일]에서는 [관찰한 동작]으로 이 개념을 확인했습니다.
```

## 운영체제 문제 묶음 O1~O5

### 1단계. 개념 환기

- 운영체제는 실행 단위, 메모리 영역, 작업 대기 방식, 물리 메모리 추상화를 관리합니다.
- 비슷해 보이는 용어는 한 축인지 서로 다른 축인지 먼저 구분하세요.
- 정의 다음에는 비용이나 문제가 발생하는 조건을 붙여야 면접 답변이 구체적입니다.

### 2단계. 접근 방향

- O1과 O3은 “무엇을 공유하는가”와 “어디에 저장되는가”를 표로 비교하세요.
- O2는 race condition과 deadlock을 별도 현상으로 정의하고 각각의 발생 조건을 적으세요.
- O4는 동기·비동기와 블로킹·논블로킹을 두 축으로 그리세요.
- O5는 가상 주소, 페이지, 디스크, 페이지 교체 순서로 흐름을 그리세요.

### 3단계. 답변 키워드와 틀

| 문제 | 답에 포함할 키워드                                           |
| ---- | ------------------------------------------------------------ |
| O1   | 독립 주소 공간, 자원 공유, IPC, 공유 메모리, 컨텍스트 스위칭 |
| O2   | 공유 상태, 실행 순서, 상호 배제, 점유와 대기, 순환 대기      |
| O3   | 호출 프레임·지역 변수, 동적 할당 객체, 수명, stack overflow  |
| O4   | 결과 대기 여부, 호출 스레드 점유 여부, 이벤트 루프, 콜백 큐  |
| O5   | 가상 주소, page, frame, swap, page fault, thrashing          |

```text
[용어 A]는 [핵심 특징]이고 [용어 B]는 [핵심 특징]입니다.
[비용/문제]는 [조건]에서 커지며, Node 코드에서는 [비동기 호출 위치]와 연결됩니다.
```

## DB 이론 문제 묶음 D1~D5

### 1단계. 개념 환기

- DB 답변은 데이터 정합성, 동시성, 중복, 조회 경로, 확장성의 관점으로 나눌 수 있습니다.
- 용어 정의만 외우지 말고 어떤 이상 현상이나 비용을 줄이려는 개념인지 설명하세요.
- 5단계 MongoDB와 10단계 SQL 실습의 관찰 결과를 근거로 사용하세요.

### 2단계. 접근 방향

- D1은 한 번의 송금을 두 UPDATE로 나누고 각 속성이 무엇을 보장하는지 연결하세요.
- D2는 격리 수준을 행으로, 세 가지 읽기 이상 현상을 열로 둔 표를 직접 만드세요.
- D3은 반복 속성, 부분 종속, 이행 종속을 순서대로 제거하는 테이블 변화를 그리세요.
- D4와 D5는 읽기 이점과 쓰기·운영 비용을 함께 적으세요.

### 3단계. 답변 키워드와 틀

| 문제 | 답에 포함할 키워드                                                                 |
| ---- | ---------------------------------------------------------------------------------- |
| D1   | 원자성, 일관성, 격리성, 지속성, 송금의 두 UPDATE                                   |
| D2   | Read Uncommitted, Read Committed, Repeatable Read, Serializable, 세 읽기 이상 현상 |
| D3   | 원자값, 부분 함수 종속, 이행 함수 종속, 키와 테이블 분리                           |
| D4   | B+Tree, 균형 높이, 범위 검색, hash 동등 비교, 쓰기 비용                            |
| D5   | 스키마 유연성, 수평 확장, 조인·트랜잭션 트레이드오프, 데이터 모델                  |

```text
[개념]은 [막으려는 문제]를 위해 사용합니다.
그 대신 [쓰기/복잡도/일관성 비용]이 있고, [5단계 또는 10단계 실습]에서 [관찰]했습니다.
```

## 자료구조 문제 묶음 S1~S5

### 1단계. 개념 환기

- 시간 복잡도는 입력 크기가 커질 때 연산 횟수가 어떻게 증가하는지를 나타냅니다.
- 평균과 최악 복잡도를 구분하고, 빠른 연산이 가능한 전제 조건을 함께 말하세요.
- 자료구조의 모양을 그린 뒤 접근·삽입 과정에서 몇 칸이나 노드를 거치는지 세어보세요.

### 2단계. 접근 방향

- S1은 접근, 탐색, 중간 삽입, 중간 삭제를 행으로 둔 비교표를 만드세요.
- S2와 S4는 평균 성능이 깨지는 충돌 또는 편향 조건을 설명하세요.
- S3은 동작 순서와 웹 개발의 실제 사례를 연결하세요.
- S5는 입력이 두 배가 됐을 때 작업량이 어떻게 변하는지 말로 풀어보세요.

### 3단계. 답변 키워드와 틀

| 문제 | 답에 포함할 키워드                                           |
| ---- | ------------------------------------------------------------ |
| S1   | 연속 메모리, 인덱스 접근, 포인터 이동, 탐색, 삽입 위치       |
| S2   | 해시 함수, 버킷, 충돌, 체이닝, 오픈 어드레싱, 최악 O(n) 조건 |
| S3   | LIFO, FIFO, 함수 호출 스택, 메시지·작업 큐                   |
| S4   | 왼쪽·오른쪽 분할, 트리 높이, 편향 트리, 회전과 균형 유지     |
| S5   | 증가율, 상수 제거, 이진 탐색, 순회, 정렬, 이중 반복          |

```text
[자료구조/복잡도]는 [전제]에서 [평균 복잡도]입니다.
[최악 조건]에서는 [더 느린 복잡도]가 될 수 있으며, [실습 코드]의 [연산]과 연결됩니다.
```

네 묶음의 3단계까지 확인한 뒤에도 막히면 마지막으로 [모범 답안과 비교하세요](./answers.md).
