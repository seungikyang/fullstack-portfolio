## 1번. 저장형 XSS

### 1단계. 개념 환기

- 저장형 XSS는 공격 문자열이 서버에 저장된 뒤 다른 사용자의 화면에서 HTML이나 스크립트로 해석될 때 발생합니다.
- 출력 인코딩은 데이터 문자를 HTML 문법이 아닌 텍스트로 바꿉니다.
- `&`를 먼저 처리해야 뒤 치환에서 새로 생긴 엔티티가 다시 변형되는 일을 피할 수 있습니다.

### 2단계. 접근 방향

- 공격 전후에 DB에 저장된 문자열 자체가 바뀌는지, 출력만 바뀌는지 구분하세요.
- `escapeHtml`에서 HTML 문법에 의미가 있는 다섯 문자를 하나씩 치환하세요.
- 제목과 본문이 출력되는 두 위치 모두 같은 함수를 통과시키세요.

### 3단계. 함수 시그니처 수준

```js
function escapeHtml(value) {
  return String(value)
    .replace(/* 앰퍼샌드 패턴 */, /* 대응 HTML entity */)
    .replace(/* 꺾쇠·따옴표 패턴 */, /* 대응 HTML entity */);
}

res.send(`${escapeHtml(/* 사용자 입력이 저장된 필드 */)}`);
```

## 2번. 반사형 XSS

### 1단계. 개념 환기

- 반사형 XSS는 요청에 포함된 입력이 응답 HTML에 즉시 반영될 때 발생합니다.
- 같은 값이라도 HTML 본문과 속성 위치에서 브라우저가 해석하는 문맥을 확인해야 합니다.

### 2단계. 접근 방향

- `q`가 응답의 어느 두 위치에 들어가는지 찾으세요.
- 1번과 같은 출력 인코딩 함수를 작성하고 두 위치에 모두 적용하세요.
- 공격 문자열이 사라지는 것이 아니라 화면에 텍스트로 보이는지 확인하세요.

### 3단계. 출력 위치 수준

```js
const q = req.query.q ?? "";

res.send(`
  <p>${escapeHtml(/* 검색어 */)}</p>
  <input value="${escapeHtml(/* 같은 검색어 */)}" />
`);
```

## 3번. SQL Injection 방지

### 1단계. 개념 환기

- 문자열 결합 쿼리는 사용자 입력을 SQL 문법 일부로 해석할 수 있습니다.
- 파라미터화 쿼리는 SQL 구조와 값을 별도로 전달합니다.

### 2단계. 접근 방향

- 안전 경로의 SQL 문자열에는 값 대신 드라이버의 자리표시자만 두세요.
- 사용자 입력은 두 번째 인자의 값 배열로 전달하세요.
- 같은 공격 입력으로 취약 경로와 안전 경로의 행 수를 비교하세요.

### 3단계. DB 드라이버 API 수준

```js
const [rows] = await pool.execute("SELECT ... WHERE name = ?", [
  /* 사용자 입력값 */
]);
```

선택 컬럼과 응답 형태는 starter의 기존 코드에 맞춰 직접 작성하세요.

## 4번. CSRF 시연

### 1단계. 개념 환기

- 브라우저는 대상 사이트의 쿠키를 교차 출처 요청에도 자동으로 실을 수 있어 CSRF가 성립합니다.
- SameSite와 CSRF 토큰은 서로 다른 층에서 교차 사이트 요청을 제한하거나 검증합니다.

### 2단계. 접근 방향

- 취약 경로와 보호 경로를 같은 쿠키로 호출해 차이를 먼저 기록하세요.
- 토큰 발급 응답과 쿠키를 유지한 뒤 보호 폼의 hidden 필드에 요청별 토큰을 연결하세요.
- SameSite 값 변경 전후의 `Set-Cookie`와 실제 브라우저 교차 출처 요청을 비교하세요.

### 3단계. 쿠키·폼 수준

```js
const sameSitePractice = /* lax 또는 strict 중 실습할 정책 */;

app.use(
  session({
    cookie: { sameSite: sameSitePractice },
  }),
);
```

```html
<input type="hidden" name="_csrf" value="<서버가 발급한 토큰 값>" />
```

## 5번. CORS 설정

### 1단계. 개념 환기

- CORS는 브라우저가 다른 origin의 응답을 프론트엔드 코드에 공개할지 결정하는 HTTP 정책입니다.
- 자격 증명을 허용할 때 모든 origin을 동시에 허용할 수 없습니다.

### 2단계. 접근 방향

- 허용 origin 목록을 배열로 두고 콜백에 들어온 origin이 목록에 있는지 확인하세요.
- origin이 없는 서버 간 요청을 허용할지 starter의 의도에 맞춰 분기하세요.
- 허용 origin과 거부 origin으로 preflight를 각각 보내 응답 헤더를 비교하세요.

### 3단계. cors 옵션 시그니처 수준

```js
const allowedOrigins = [/* 허용할 정확한 origin */];

cors({
  origin(origin, callback) {
    if (!origin || allowedOrigins.includes(origin)) {
      return callback(null, true);
    }
    return callback(/* 거부 오류 */);
  },
  credentials: /* 쿠키 등 자격 증명 허용 여부 */,
});
```

## 6번. 시크릿 노출 사후 대응

### 1단계. 개념 환기

- Git에서 파일을 삭제해도 이전 커밋에는 값이 남아 있을 수 있습니다.
- 노출된 시크릿은 더 이상 비밀이 아니므로 이력 정리보다 폐기와 교체가 먼저입니다.

### 2단계. 접근 방향

- 폐기 가능한 더미 값으로 현재 파일과 커밋 이력의 차이를 확인하세요.
- 대응을 값 교체, 기존 자격 증명 무효화, 영향 범위 조사, 이력 정리 순서로 적으세요.
- 각 단계에 담당자와 검증 방법을 한 줄씩 붙이세요.

### 3단계. 확인 명령과 기록 틀

## 7번. 비밀번호 정책 점검

### 1단계. 개념 환기

- bcrypt cost는 해시 계산 비용을 조절하고 salt는 같은 비밀번호도 다른 해시가 나오게 합니다.
- 인증 오류를 지나치게 구체적으로 반환하면 존재하는 계정을 추측할 수 있습니다.

### 2단계. 접근 방향

- 6단계의 회원가입, 로그인 라우트와 bcrypt 호출 위치를 각각 찾으세요.
- 최소 길이 검증이 해시 전에 실행되는지 확인하세요.
- 동일 원문을 두 번 해시한 결과와 두 로그인 실패 응답을 비교하세요.

### 3단계. API와 검증 수준

```js
if (password.length < /* 정책 길이 */) {
  return res.status(/* 입력 오류 상태 */).json(/* 일반화된 오류 */);
}

const hash = await bcrypt.hash(password, /* 정책 cost */);
const matches = await bcrypt.compare(password, hash);
```

## 8번. 의존성 취약점 스캔

### 1단계. 개념 환기

- 취약점 보고서는 패키지 이름, 영향 버전, 심각도, 수정 가능 버전을 함께 읽어야 합니다.
- 자동 수정은 호환성을 깨뜨릴 수 있으므로 변경 diff와 테스트가 필요합니다.

### 2단계. 접근 방향

- 현재 lockfile 기준 보고서를 저장하고 high 이상 항목만 먼저 분류하세요.
- 직접 의존성과 전이 의존성을 구분하고 권고 버전의 변경 범위를 확인하세요.
- 수정 후 같은 스캔과 프로젝트 테스트를 다시 실행하세요.

### 3단계. 실행 명령 수준

```bash
npm audit --omit=dev
npm audit --omit=dev --json
./gradlew dependencyCheckAnalyze
```

Java 명령은 11단계 프로젝트와 플러그인을 직접 구성한 경우에만 실행하세요.

## 9번. OWASP Top 10 자기 정리

### 1단계. 개념 환기

- OWASP 분류는 공격 기법만이 아니라 설계, 구성, 공급망, 탐지 실패까지 포함합니다.
- 항목 이름을 번역하는 것보다 “어떤 실패가 어떤 피해를 만드는가”를 설명하는 것이 중요합니다.

### 2단계. 접근 방향

- 각 항목을 실패한 통제, 가능한 피해, 자신의 트랙 근거의 세 칸으로 정리하세요.
- XSS와 SQL Injection은 Injection과 연결하되 다른 항목에도 억지로 중복 배치하지 마세요.
- 직접 실습하지 않은 항목은 아는 척하지 말고 확인할 코드나 로그를 적으세요.

### 3단계. 한 줄 답변 틀

```text
이 워크북에서는 [트랙/파일/실습]에서 [방어 또는 확인 방법]과 연결됩니다.
```
