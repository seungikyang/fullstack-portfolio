# 인성·협업 10문제 — 4지선다

[단계 설명](./README.md) · [웹에서 채점하기](../quiz/index.html?bank=written&category=behavioral) · [완료 체크](../student-checklist.md)

## 문제 진행 방식

이 문서는 4지선다 문제입니다. 보기 네 개 중 가장 알맞은 답 하나를 고른 뒤 접힌 정답·해설을 확인하세요. 웹에서는 채점·오답 복습·진행 기록을 사용할 수 있습니다.

개인 경험을 묻던 문항은 근거 있는 답변 방식을 선택하는 문제로 바꿨습니다. 선택지의 원칙이 본인의 실제 경험을 대신하지는 않습니다.

### B01. 어려운 경험의 답변 방식

어려운 경험의 답변 방식 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 가장 큰 회사의 장애를 자기 경험이라고 한다.
2. 결과 없이 고생했다는 표현만 반복한다.
3. 실제 상황·과제·본인 행동·확인한 결과를 STAR로 연결한다.
4. 모든 문제를 동료 탓으로 돌린다.

<details>
<summary>정답·해설 확인</summary>

**정답: 3번**

STAR는 Situation, Task, Action, Result입니다. 실제 행동과 확인한 결과를 구분해서 제시합니다.

</details>

### B02. 의견이 갈릴 때

의견이 갈릴 때 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 상대 의견을 듣지 않고 모두 덮어쓴다.
2. 의견 충돌을 감추고 혼자 결정한다.
3. 기술 근거 대신 상대를 비난한다.
4. 공통 목표와 근거를 확인하고 대안을 비교해 합의한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 4번**

근거와 실험으로 차이를 줄이고 결정 과정을 공유합니다. 개인 승리보다 업무 목표를 우선합니다.

</details>

### B03. 강점과 약점의 근거

강점과 약점의 근거 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 강점은 실제 사례로, 약점은 영향과 보완 행동으로 설명한다.
2. 어떤 질문에도 약점이 전혀 없다고 답한다.
3. 강점은 경험 없이 형용사로만 나열한다.
4. 약점을 동료의 문제로 바꿔 설명한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 1번**

추상적인 성격 표현보다 확인 가능한 행동과 개선 노력이 근거가 됩니다.

</details>

### B04. 새 기술의 학습 방법

새 기술의 학습 방법 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 설치만 하면 사용 경험이 완성된다.
2. 공식 문서·작은 실험·검증·프로젝트 적용 순서로 확인한다.
3. 오류 메시지를 읽지 않고 정답만 복사한다.
4. 배운 기술을 검증 없이 바로 운영에 적용한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 2번**

작게 실행해 결과를 확인하고 근거를 남깁니다. 읽은 내용과 구현 경험을 구분합니다.

</details>

### B05. 실수 대응

실수 대응 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 발견한 오류를 숨기고 로그를 삭제한다.
2. 원인과 무관하게 다른 사람을 탓한다.
3. 영향을 공유하고 피해를 줄인 뒤 원인과 재발 방지를 확인한다.
4. 노출된 비밀값을 계속 사용한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 3번**

조기 공유와 영향 최소화가 우선입니다. 이후 원인·회귀 검증·예방 절차를 개선합니다.

</details>

### B06. 마감이 임박했을 때

마감이 임박했을 때 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 모든 검증을 삭제하고 완료했다고 보고한다.
2. 일정을 숨긴 채 기능을 무한히 추가한다.
3. 영향을 알리지 않고 모든 기능을 포기한다.
4. 필수 기능과 위험을 정리하고 범위를 협의하며 검증 시간을 확보한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 4번**

우선순위와 남은 위험을 공유합니다. 범위와 일정은 협의하고 필수 검증을 유지합니다.

</details>

### B07. 팀 역할 설명

팀 역할 설명 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 실제로 맡은 책임·협업 방식·결과를 구체적으로 연결한다.
2. 팀 전체 성과를 전부 자기 성과로 말한다.
3. 역할은 없이 직함만 나열한다.
4. 동료의 비공개 개인 정보를 근거로 공개한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 1번**

팀의 성과와 본인의 기여를 구분합니다. 실제 수행한 범위만 설명합니다.

</details>

### B08. 1년 후 목표

1년 후 목표 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 한 달 안에 모든 기술의 전문가가 된다고 약속한다.
2. 직무에 필요한 역량과 구체적 행동·확인 기준을 정한다.
3. 목표는 있지만 실행 계획은 필요 없다고 한다.
4. 자격증 이름만 나열하고 업무 연결은 생략한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 2번**

목표에는 실행 계획과 확인 기준이 필요합니다. 현재 수준과 직무 요구를 함께 고려합니다.

</details>

### B09. 회사 지원 동기

회사 지원 동기 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 회사를 조사하지 않고 이름만 칭찬한다.
2. 모든 회사에 같은 이름의 지원 동기를 쓴다.
3. 조사한 업무·기술 요구와 본인의 확인된 학습·기여 방향을 연결한다.
4. 존재하지 않는 회사 프로젝트를 아는 척한다.

<details>
<summary>정답·해설 확인</summary>

**정답: 3번**

실제로 조사한 정보와 확인된 경험을 연결합니다. 사실을 지어내지 않습니다.

</details>

### B10. 면접 마지막 질문

면접 마지막 질문 — 알맞은 설명 또는 답변 방식을 고르세요.

1. 채용 공고에 이미 적힌 내용만 반복해서 묻는다.
2. 면접관 개인의 비밀번호를 요청한다.
3. 질문 시간이 정해졌는데 답변과 무관한 이야기를 계속한다.
4. 신입의 업무·학습 지원·리뷰 방식 등 조사 후 궁금한 점을 묻는다.

<details>
<summary>정답·해설 확인</summary>

**정답: 4번**

업무 이해에 도움이 되는 질문을 준비합니다. 이미 확인한 정보와 실제 궁금한 점을 구분합니다.

</details>
