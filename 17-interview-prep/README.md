# 17단계 면접 대비 통합

[HTML 목차](../index.html) · [기술 카드](./interview-cards.md) · [자기소개](./self-intro-templates.md) · [인성·STAR](./behavioral-questions.md) · [프로젝트 설명](./project-pitch-template.md) · [완료 체크](../student-checklist.md)

## 목표

1~16단계에서 분산돼 있던 면접 질문을 한 파일로 모아, 면접 직전에 한 자리에서 복습할 수 있게 만듭니다. 자기소개·기술 면접·인성 면접 세 영역을 모두 다룹니다.

이 단계는 **4지선다 선택 → 채점 → 해설 확인 → 오답 복습**으로 진행합니다. 기술·통합 면접 77문제, 인성·협업 10문제, 자기소개 구성 4문제, 프로젝트 설명 8문제입니다. 개인 경험을 묻던 문항은 적절한 답변 방식을 고르는 문제로 바꿨습니다.

## 기술을 쓰는 이유와 동작 흐름

처음 보는 용어는 [전체 기술 안내서](../technology-guide.md)와 함께 읽으세요. 아래 흐름은 실습을 이해하기 위한 안내이며, 빈칸과 완료 체크는 직접 진행합니다.

이 단계는 새 런타임 기술(프로그램을 실행할 때 쓰는 기술)을 추가하지 않습니다. 앞선 기술의 필요성과 동작을 자기 경험·코드 근거로 연결하는 역할입니다.

| 정리 방법 | 무엇이고, 왜 필요한가요? | 이 실습에서는 어떻게 쓰나요? |
| --- | --- | --- |
| 기술 카드 | 개념별 질문을 모은 복습 도구입니다. 기술 이름을 아는 것과 동작을 설명할 수 있는 것을 구분하게 합니다. | [interview-cards.md](./interview-cards.md)의 네 보기에서 정의·사용 이유·코드 연결을 고릅니다. |
| 프로젝트 설명 | 사용자 기능을 출발점으로 기술의 역할을 설명하는 방식입니다. 기술을 나열하는 대신 도입 이유를 보여줍니다. | [project-pitch-template.md](./project-pitch-template.md)에서 실제 기능·스택·검증·한계에 맞는 설명을 고릅니다. |
| STAR | 상황(Situation)·과제(Task)·행동(Action)·결과(Result)의 순서로 경험을 정리하는 방법입니다. 본인이 실제로 한 행동과 확인한 결과를 분명히 합니다. | [behavioral-questions.md](./behavioral-questions.md)에서 실제 경험을 근거로 한 답변 원칙을 고릅니다. |

**설명 한 개를 만드는 순서:** 직접 실행한 기능 선택 → 필요했던 문제 적기 → 관련 파일에서 사용 기술 찾기 → 요청·데이터의 이동 순서 설명 → 실행 기록으로 확인한 결과와 남은 한계 구분 → 소리 내어 연습.

**직접 관찰하기:** 설명 속에서 “사용했다”, “구현했다”, “검증했다”는 말마다 각각 파일·본인 변경·실행 결과를 가리킬 수 있는지 확인하세요. 제공된 Career Hub를 실행한 경험과 직접 만든 기능을 구별합니다. 막힌 개념은 해당 트랙으로 돌아가고, 확인하지 않은 성능 수치나 배포 성과는 넣지 않습니다.

## 실행 방법

저장소 루트에서 실행합니다.

```bash
npm install
npm run serve:workbook
```

목차의 **서술형 전환 4지선다**에서 원하는 분야를 선택하거나 다음 링크로 시작합니다.

- [기술·통합 면접 77문제](../quiz/index.html?bank=written&category=technical)
- [인성·협업 10문제](../quiz/index.html?bank=written&category=behavioral)
- [자기소개 구성 4문제](../quiz/index.html?bank=written&category=intro)
- [프로젝트 설명 8문제](../quiz/index.html?bank=written&category=project)

답을 선택하고 **정답 확인**을 누릅니다. **틀린 문제**로 복습하며, 문서로 읽을 때는 각 문제의 접힌 정답·해설을 확인합니다.

## 완료 기준

- 자기소개 구성 4문제를 선택하고 채점했습니다.
- 1~16단계와 통합 기술 카드 77문제를 선택하고 채점했습니다.
- 인성·협업 10문제에서 STAR와 근거 있는 답변 방식을 확인했습니다.
- 프로젝트 설명 8문제에서 실제 기능·스택·검증·한계를 구분했습니다.
- 오답을 다시 풀고 해설에 인용할 수 있는 실제 코드 위치를 확인했습니다.

완료로 표시하기 전 [학습 근거 4종](../student-checklist.md#단계마다-남길-4종-근거)에 실행 명령, 채점·복습 결과, 고친 오개념, 확인한 코드 위치를 기록합니다. 선택형 정답은 개인의 실제 구현·협업 경험을 대신하지 않습니다.

## 취업 연결

신입 면접에서는 코드 자체뿐 아니라 본인이 맡은 범위와 해결 과정을 설명하는 능력도 함께 확인될 수 있습니다. 같은 프로젝트라도 "GitHub에 있습니다"보다 "이 기능에서 X 문제를 만났고 Y로 해결했습니다"처럼 근거를 붙이면 경험 범위가 명확해집니다.

이 단계가 끝나면 준비한 질문에 실행 로그와 자기 코드 위치를 붙여 답하는 상태를 목표로 합니다. 준비하지 않은 질문에는 모르는 범위를 구분해 답합니다.

## 답변 원칙

1. **자기 코드를 근거로**. "교과서에서 봤습니다"가 아니라 "Career Hub의 server/auth.js에서 직접 다뤘습니다".
2. **30초·1분·3분 버전을 준비**. 면접관이 듣고 싶은 시간에 맞춰 답변 길이를 조정할 수 있어야 합니다.
3. **모르는 건 모른다고**. 거짓 자신감보다 "그 부분은 학습 중이지만 비슷한 X 개념과 연결됩니다"가 더 신뢰를 줍니다.
4. **숫자를 곁들이기**. "빠르게"보다 "응답 시간을 X ms에서 Y ms로 줄였습니다".
5. **소리 내어 연습**. 머릿속으로만 정리하면 실제 면접에서 막힙니다.

## 복습 원칙

선택지의 해설을 실제 파일과 대조합니다. Node·Express 학습 경험을 Spring 구현 경험으로 바꾸어 말하지 않습니다. 모르는 범위와 다음 학습을 구분하고, 확인하지 않은 성능 수치나 배포 성과를 주장하지 않습니다.
