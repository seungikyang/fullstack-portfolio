# 자기소개 템플릿 (30초 · 1분 · 3분)

면접 첫 질문은 거의 자기소개로 시작합니다. 세 가지 길이를 미리 준비해, 면접관이 원하는 시간에 맞춰 답할 수 있게 만드세요.

## 30초 버전 (엘리베이터 피치)

세 문장 안에 끝내세요. 핵심은 "나는 누구이고, 무엇을 만들었으며, 왜 이 회사인가"입니다.

템플릿.

> 안녕하세요. {이름}입니다. {기간} 동안 React·Node·Spring으로 풀스택 학습을 마쳤고, 그 결과물로 {프로젝트 한 문장 소개}를 만들었습니다. {회사 한 가지 특성}이 제 학습 방향과 잘 맞아 지원했습니다.

작성 칸.

```
안녕하세요. ____입니다.
____ 동안 ____ 스택으로 ____을 만들었습니다.
____한 이유로 ____ 회사에 지원했습니다.
```

## 1분 버전

다섯 문장. 30초 버전에 "어려웠던 점 + 배운 점"을 더합니다.

템플릿.

> 1) 자기 정의 한 문장.
> 2) 학습 흐름 한 문장 ("HTML부터 Docker까지").
> 3) 가장 자신 있는 프로젝트 한 문장.
> 4) 그 프로젝트에서 어려웠던 한 가지와 해결법.
> 5) 회사 지원 이유.

작성 칸.

```
1) ____
2) ____
3) ____
4) ____
5) ____
```

## 3분 버전

7~9문장. 1분 버전에 "구체 기술 선택 이유 + 검증 방법 + 다음 학습 영역"을 더합니다.

체크 항목.

- 자기 정의 (전공, 학습 기간, 강점 한 가지).
- 학습 흐름 (1~14단계 또는 1~17단계의 핵심 키워드 5개 이내).
- 대표 프로젝트 한 개. 해결한 문제, 사용 스택, 본인의 기여.
- 그 프로젝트에서 만난 한 가지 어려움과 해결 과정 (구체적 코드 또는 명령).
- 검증 방법 (테스트 통과, 빌드 통과, 직접 확인).
- 다음에 학습할 영역 (자격증, 코딩테스트, 특정 기술).
- 회사 지원 이유 (구체적이고 정직하게).

작성 칸.

```
[자기 정의]
____

[학습 흐름]
____

[대표 프로젝트]
____

[어려웠던 점과 해결]
____

[검증 방법]
____

[다음 학습 영역]
____

[지원 이유]
____
```

## 자기소개에서 피해야 할 것

- 거짓 자신감. "모든 기술을 다 잘합니다"보다 "이 영역은 자신 있고, 저 영역은 학습 중"이 신뢰를 줍니다.
- 외운 티가 나는 문장. 자연스러운 대화체로 말하세요.
- 회사 이름 틀리기. 특히 비슷한 SI 업체끼리는 절대 헷갈리지 마세요.
- 시간 초과. 30초로 요청받았는데 1분 답하면 마이너스입니다.

## 연습 방법

1. 작성 칸을 채운 뒤 소리 내어 말합니다.
2. 휴대폰으로 녹음해 다시 들어봅니다.
3. 너무 빠르거나 느린 부분을 표시합니다.
4. 친구나 가족 앞에서 두 번 더 말합니다.
5. 길이가 30초·1분·3분에 정확히 맞을 때까지 다듬습니다.
