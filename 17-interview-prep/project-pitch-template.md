# 프로젝트 3분 설명 템플릿

면접에서 가장 자주 듣는 질문 중 하나가 "포트폴리오를 직접 설명해보세요"입니다. 3분 안에 끝낼 수 있도록 미리 준비합니다.

기본 후보는 `08-fullstack-portfolio-project`(Career Hub)입니다. 11단계 Spring 게시판도 보강 트랙 결과물로 활용 가능합니다.

## 3분 설명 구조

| 단계 | 시간 | 내용 |
| --- | --- | --- |
| 1. 한 문장 정의 | 15초 | "X를 위한 Y 앱입니다." |
| 2. 사용 스택 | 20초 | 프론트, 백, DB, 인증, 배포. |
| 3. 핵심 기능 3개 | 60초 | 한 기능당 20초씩. |
| 4. 어려웠던 점 1개 | 30초 | 구체적 문제 + 어떻게 해결. |
| 5. 검증 방법 | 20초 | 어떤 명령으로 동작 확인. |
| 6. 한계와 다음 계획 | 15초 | 정직한 한계. |

총 3분.

## 두 번째 프로젝트 후보 (11단계 Spring 게시판)

Career Hub 외에 Spring으로 작성한 게시판을 보조 포트폴리오로 활용할 수 있습니다.

### 한 문장 정의

```
같은 게시판 API를 Express와 Spring Boot 두 스택으로 구현해, 두 진영의 패턴 차이를 직접 비교한 프로젝트입니다.
```

### 어필 포인트

- 같은 도메인을 두 스택으로 만들어보았다는 비교 경험.
- Controller/Service/Repository 계층 분리.
- JPA 변경 감지로 명시적 save 호출 없이 UPDATE가 발생하는 이유 설명 가능.
- `@WebMvcTest`로 Controller 통합 테스트 작성 경험.

## 3분 설명에서 피해야 할 것

- 기능 나열만 늘어놓기. "회원가입 있고, 로그인 있고, CRUD 있고..."는 5초만에 끝납니다.
- 어려웠던 점을 "특별히 없었습니다"로 답하기. **반드시 한 가지 준비**.
- 외운 티가 나는 단조로운 톤. 자연스러운 설명조로.
- 검증 방법을 빠뜨리기. "동작합니다"가 아니라 "X 명령으로 통과를 확인했습니다".

## 연습 절차

1. 위 작성 칸을 모두 채웁니다.
2. 소리 내어 말하며 스톱워치로 시간을 잽니다.
3. 3분에 정확히 맞지 않으면 줄이거나 늘립니다.
4. 한 단계씩 줄여 1분 버전과 30초 버전도 만듭니다.
5. 다음 단계는 면접관의 후속 질문 예상하기. 예. "왜 MongoDB 대신 JSON 파일인가요?", "JWT 만료 시 어떻게 대응하나요?"
